# BMS-IR Arena：つないだ確認の手順

B1〜B4 で入れた Arena の機能を、実際のサーバーにつないで確かめる手順を 1 本にまとめたものです。
自動テストは loopback の偽サーバーまでです。ここにある確認は、人が BMZ を 2 つ動かして行います。
機能の説明は [ARENA.md](ARENA.md)、サーバーのメッセージは [ARENA_SERVER_MESSAGES.md](ARENA_SERVER_MESSAGES.md) を見てください。

- 各手順の「合格」が、見るものです。合わなければ、その手順の番号と見たものを記録してください。
- 項目名は `ARENA_SERVER_MESSAGES.md` に合わせています。サーバーのログに出るメッセージの名前で見ます。
- 秘密（ゲームトークン、許可リストの値）は、記録にも PR にも書かないでください。

## 0. 本番で試す前の条件（オペレーターが行う）

BMS-IR の本番サーバーは、BMZ の版とビルドが許可リストに入っていないと拒否します
（`unsupported_client` / `unsupported_build`。BMZ は「このビルドは更新が必要です」と表示して、再接続を繰り返しません）。

試す前に、BMS-IR 側で次を行います。**値はこの文書にも Issue にも書きません。**

1. 試すビルドの `client_version`（このリポジトリでは `bmz-bmsir-0.1.0`。`arena/mod.rs`）を、flavor `bmz-player` の版の許可リストに入れる。
2. 試すビルドの `build_hash`（ビルドのコミット `BMZ_BUILD_COMMIT`、40 桁）を、flavor `bmz-player` のビルドの許可リストに入れる。
   `-dirty` や `unknown` のビルドは入れられません。コミット済みの状態でビルドします。
3. BMS-IR 側の `bmz-player` flavor が本番に入っていること（BMS-Mania/IR#1591）。
4. 許可リストのキー名は、版が `BMSIR_ARENA_ALLOWED_BMZ_CLIENT_VERSIONS`、ビルドが `BMSIR_ARENA_ALLOWED_BMZ_BUILD_HASHES` です（値はここに書きません）。
   Arena oraja のキーとは別で、互いの flavor を通しません。BMZ の値が空でも、Arena の `/healthz` は落ちません。

本番に入るまでは、次の「手元のサーバー」で行います。

## 1. 準備

### 1-1. 手元の Arena サーバー

1. BMS-IR のリポジトリの Arena サーバー（`tools/bmsir_arena_server.py`）を、手元で起動する。
2. 開発用の許可として、サーバーの環境変数 `BMSIR_ARENA_ALLOW_DEV_CLIENT=1` を付けて起動する（許可リストを使わずに BMZ を通す）。
3. サーバーのログ（受け取ったメッセージの `type`）を見られるようにしておく。

**合格**：サーバーが起動し、ログが読める。

### 1-2. 手元のサーバーに向けた BMZ のビルド

1. ビルド時に `BMZ_BMS_IR_BASE_URL=http://127.0.0.1:<ポート>`（手元のサーバーの IR のベース URL）を付けて `cargo build -p bmz-player --release` する。
   Arena はこの URL から、同じホストの `ws://…/new/arena/ws/client` に接続します（Arena 専用の上書きはありません）。
2. 接続先は BMS-IR のホストだけに制限されています（`fork_policy::ensure_arena_url_allowed`）。他のホストは使えません。

**合格**：起動して「BMZ メニュー → IR」に BMS-IR の 1 枠だけが出る。

### 1-3. 2 つのプロファイル

対戦には 2 人が必要です。1 台の PC なら、プロファイルを 2 つ作り、BMZ を 2 つ起動します。

1. プロファイル A、B を作る（別々の `--profile` で起動する。[settings.md](../settings.md) のプロファイルの節）。
2. それぞれで、別の BMS-IR アカウントでログインする（手元のサーバーのアカウント。トークンの作り方は手元のサーバー側の手順による。**未確認**）。
3. 両方に同じ 7KEY の曲を入れておく（`chart_check` で `available=true` にするため）。
   片方にだけ持たせた譜面は、「持っていない側」の確認（手順 5）に使う。
4. 2 つの BMZ は、同時に別々のウィンドウで動かす（片方が背面でも動くようにしておく）。

**合格**：A と B がそれぞれ別のアカウントでログイン済み。

## 2. 接続（B1）

| # | 操作 | 合格 |
|---|---|---|
| 2-1 | Arena の設定が OFF のまま選曲まで進む | サーバーに接続が来ない（BMZ のログにも接続の記録がない） |
| 2-2 | BMS-IR にログインしていない状態で ON にする | 「BMS-IR にログインしていません」と出る。接続しない |
| 2-3 | ログインして ON にする | 「接続済み」。サーバーに `hello`、続けて `state`（`select`）と `ping` が来る。`hello` に `client_flavor=bmz-player`、`ruleset_profile` がプロファイルのルール（`lr2` / `oraja`）。トークンそのものは来ない（`passmd5` のみ） |
| 2-4 | 「BMZ メニュー → IR」を見る | `arena_status` に `player` があれば、「レート」と「対戦数」が出る。時計のずれ（ms）と往復が出る |
| 2-5 | ネットワークを切る／サーバーを止める | 約 20 秒で切断が表示され、5 秒後に再接続を試みる。最初の切断から 30 秒を過ぎたら 30 秒おき |
| 2-6 | 戻す | 「接続済み」に戻り、`hello` と `state` が来る。レートと対戦数が復活する（切断中は消える） |
| 2-7 | 許可されていないビルドで試す（本番、または許可なしのサーバー） | 「拒否されました。このビルドは更新が必要です」。再接続を繰り返さない |
| 2-8 | 同じアカウントを別の BMZ で接続する | 先の側に `replaced`。「自動では再接続しません」と出て、「再接続」を押すまでつなぎ直さない |
| 2-9 | OFF に戻す | 接続が切れ、「オフ」になる |
| 2-10 | 普通の選曲 → プレイ → 結果 | Arena が ON でも OFF でも、プレイ・スコア保存・BMS-IR への送信がふだんどおり |

## 3. ルームと推薦（B2-1）

A と B が接続済みで、選曲画面にいる状態から。

| # | 操作 | 合格 |
|---|---|---|
| 3-1 | 画面の右上に「Arena」の窓が出る | 選曲画面と結果画面に、接続済みのときだけ出る。決定・プレイ中には出ない（結果画面の窓は、結果と全員の進み具合だけ） |
| 3-2 | A が「ルームを作る」 | サーバーに `room_entry`（`match_mode=private`、`room_code` なし、`score_rule=exscore`、`forced_gauge=free`、`chart_scope=free`、`ln_mode=LN`、`nomination_policy=all`、`nomination_seconds=60`、`option_seconds=10`、`allowed_play_modes=[7]`、`spectator_public=false` など全項目）。A の窓にコードが出る |
| 3-3 | B が A のコードで「入る」（パスワードを付けた場合は同じパスワード） | `room_entry`（`room_code`、あれば `room_password` だけ）。両方の窓に、2 人の名前とホスト（A）が出る。パスワードを間違えるとサーバーの通知が出て入れない |
| 3-4 | A、B が「準備 OK」を押す | `room_ready` と `state`（`ready=true`）が届く。窓の名前の横が「準備 OK」になる。試合が決まり（`match_reserved`）、段階が「参加者を集めています」→「譜面を推薦してください」と進み、残り秒数が減る |
| 3-5 | A が選曲で譜面を選び「選択中の譜面を推薦」 | `chart_nominate`（`chart_hash` は MD5）。「推薦を送りました」。もう一度は押せない。B は「スキップ」でも推薦でもよい（`chart_nomination_skip`） |
| 3-6 | 推薦が公開され、譜面が決まる | 「推薦が公開されました…」→「譜面が決まりました」。曲名とアーティストが出る |
| 3-7 | 譜面が決まった直後 | `chart_check` が両者から届く。持っている 7KEY は `available=true`、`play_mode=7`。持っていない譜面は `false`。5/9/10/14KEY の譜面は `false` |
| 3-8 | （ホスト A）「ルームの設定を送り直す」 | `room_settings` が `ln_mode` 以外の全項目で届く。B の窓では見えない（ホストのボタン） |
| 3-9 | 試合の前に「ルームから抜ける」 | `queue_cancel`。ルームが消える（B は残る。ホストが抜けると、最古参加者に移る） |

## 4. 取り消しと外された場合（B2-1、B4 の文面）

| # | 操作 | 合格 |
|---|---|---|
| 4-1 | 準備 OK の人数を足りなくして時間切れにする | 試合が取り消され、窓に**日本語の文**（例：「準備 OK の人が足りず、試合を取り消しました」）が出る。理由コード（`not_enough_ready_players`）は出ない。準備 OK が外れる。ルームは残る |
| 4-2 | 譜面を持っていない人がいる状態にする | 「譜面を持っている人が足りず…」（`not_enough_players_with_chart`）、または別の候補になる |
| 4-3 | 読み込みを遅らせる（`load_timeout`、120 秒） | 「読み込みが間に合わない人がいて…」 |
| 4-4 | 6 言語（日本語、English、한국어、简体、繁體（台湾）、繁體（香港））に切り替えて、4-1 を見る | どの言語でも、理由ごとの文が出る。コードは出ない |
| 4-5 | サーバーの知らない理由（サーバー側で未登録の理由を返す、または偽のサーバー） | 「試合が取り消されました」だけが出る |
| 4-6 | 他のプレイヤーから外される（ホストがキック、`match_released`） | 「試合から外されました」。ルームに残る／出るのはサーバーの通知による |
| 4-7 | ホストがルームを解散する（サーバー側の操作） | 「ホストがルームを解散しました」。窓のルームの表示が消える |
| 4-8 | 試合中（READY またはプレイ中）にホストがルームを解散する | `room_disbanded`（`match_id` 付き）で「ルームが解散されたため試合が取り消されました」。ESC などのロックが外れ、曲は通常のプレイとして続く（スコア保存・BMS-IR への送信はふだんどおり）。解散後に `final` は送られない |
| 4-9 | 棄権が確定する／再推薦になる | `forfeit_accepted` と `retry_reason`・`chart_missing` の理由が、6 言語の文で出る（コードは出ない）。知らない理由は汎用の文 |

「9 件」は、`not_enough_players_with_chart`、`load_timeout`、`loaded_longnote_contract_mismatch`、`not_enough_ready_players`、
`not_enough_option_ready_players`、`not_enough_connected_players`、`not_enough_players_after_withdrawal`、`reservation_timeout`、`server_fault`。
`server_fault` のときは、ルームから外れる（サーバーが取り消す）ので、入り直す。

## 5. オプション・読み込み・同時開始（B2-2）

譜面が決まったあとから。

| # | 操作 | 合格 |
|---|---|---|
| 5-1 | 全員の `chart_check` が通る | 段階が「オプション選択中（n / m 人が準備完了）」。窓に「READY（今のオプションで送る）」が出る |
| 5-2 | 選曲画面でオプション（1P 配置、FLIP）を変えてから「READY」を押す。またはそのまま放置 | `option_ready` が 1 回だけ届く。`play_option` = 1P + 10 × 2P + 100 × FLIP になる。放置の場合は締切の 0.25 秒前に自動で届く。H-RANDOM など Arena にない配置は NORMAL として送られる |
| 5-3 | `prepare` が届く | 決定画面を通らずに、READY の画面になる。読み込み中の表示が出る。選曲画面のオプションは書き換わらない |
| 5-4 | RANDOM の並びを見比べる（サーバーの `random_seed` は同じ） | 2 台の並び（RANDOM 系の配置にした場合）が一致する |
| 5-5 | 読み込みが終わる | サーバーに `play_ready` が 1 回届く。`totalnotes` は譜面のノーツ数（LN の部屋は LN 1 本 = 1）。READY の演出が終わるのを待たず、読み込み完了で届く |
| 5-6 | 全員の `play_ready` が揃い、`start` が届く | READY のまま止まる（演出が終わっていても始まらない） |
| 5-7 | サーバー時刻が `start_at` に着く | 2 台の曲の 0 秒がほぼ同時に始まる。スキンの `playstart` が違う 2 台でも揃う（動画の撮影、または効果音の聞き比べで確かめる。許容は 1 フレーム程度） |
| 5-8 | 試合が決まっている間に、選曲で決定を押す | トーストが出て、通常の曲は始まらない |
| 5-9 | READY の間に戻るキー | `forfeit` が届き、「棄権しました」と出る。相手側は、試合が取り消される／棄権で続く（サーバーの動きによる） |

## 6. live と final（B3）

手順 5 から続けて、最後まで遊びます。

| # | 操作 | 合格 |
|---|---|---|
| 6-1 | プレイが始まったあと | サーバーに `live` が 1 秒に 1 回以下で届く。`seq` が 1 から増える。`exscore`、`processed_notes`、`max_combo` が減らない。`start_at` の 2 秒より前には届かない（`too_early` の通知が出ない）。窓に全員の進み具合が出る |
| 6-2 | BAD/POOR を出す | `combo_break` が BAD + POOR、`minbp` が BAD + POOR + 空 POOR で増える |
| 6-3 | プレイ中に ESC、E2+E3、E1+E2 長押し | どれでも中断せず、トースト「Arena の対戦中は、プレイを途中で抜けられません」が出る |
| 6-4 | 最後まで遊ぶ（クリア） | 結果画面より前に `final`（`state=complete`、`clear_type` が 2 以上、`processed_notes` = ノーツ数、`seq` は `live` の続き）が届く |
| 6-5 | ゲージを尽きさせて終わる | `final` が `state=hard_fail`、`clear_type=1` |
| 6-6 | `result` が届く | 結果画面の Arena の窓に、順位・名前・EX・クリアが出る。棄権した人は `DNF`。プレイ・スコア保存・BMS-IR への送信は、通常のプレイと同じ（ルールと LN の方針はこの試合の値） |
| 6-7 | 結果画面で、IR の送信が終わるのを待つ | 送信が終わってから、`state`（`result`、`ready=true`、ルームで準備 OK のとき）が届く |
| 6-8 | 試合の後 | 通常のプレイ、練習、AUTOPLAY、リプレイ、コースが始められる。それぞれのとき、サーバーが見る `state` が `play` / `practice` / `autoplay` / `replay` / `course` になる |

## 7. 切断・再接続（B3、B4）

| # | 操作 | 合格 |
|---|---|---|
| 7-1 | プレイ中にネットワークを切り、曲が終わってから戻す（30 秒以内） | 再接続のあと `final`、`state` の順に届く。曲は始め直さない。`result` が出る。サーバーが受け取り済みなら `invalid_final` の通知が出ることがあるが、試合は終わらない |
| 7-2 | READY（読み込み済み、`start` の前）でネットワークを切り、戻す | 再接続のあと `play_ready`、`state` の順に届く。READY のまま `start_at` を待つ（開始待ちなしで進まない）。曲は始め直さない |
| 7-3 | 読み込み中（`prepare` の後、`play_ready` の前）でネットワークを切り、読み込みが終わってから戻す | 再接続のあと `play_ready` が届く。READY は開始待ちのまま（B4 で直した） |
| 7-4 | `start` を逃すほど長く（5 秒以上）切って、`start_at` を過ぎてから戻す | `match_resume`（`playing`）を受け、READY が止まらず始まる（遅れて始まる。B4 で直した） |
| 7-5 | ルームにいる状態でネットワークを切って戻す | 同じコードのルームが画面に戻る。参加者の一覧は次の `room_status` で埋まる（再接続の直後には空のことがある） |
| 7-6 | 切断が 30 秒を超える | サーバーが切断として棄権にする。戻ったあと、手元の試合は消え、結果の窓に反映される（サーバーによる） |
| 7-7 | 試合の途中で BMZ を終了して開き直す | 曲には戻れない（サーバーが切断として棄権にする）。通常のプレイに戻れる |
| 7-8 | 前の試合の `match_cancelled` / `match_released` が遅れて届く（偽のサーバーでだけ確かめられる。自動テストあり） | 今の試合は消えない |

## 8. 棄権（B3）

| # | 操作 | 合格 |
|---|---|---|
| 8-1 | 選曲画面（READY の前の段階）で「棄権する」 | `forfeit` が届き、「棄権しました」。相手側の試合は続く／取り消しになる（サーバーによる） |
| 8-2 | プレイ中（時計が始まったあと）に BMZ のウィンドウを閉じる | `forfeit` が届いてから閉じる。相手側の結果に `DNF` が出る |
| 8-3 | `final` を出したあとに「棄権する」 | 何も送られない（サーバーが結果を確定する） |

## 9. 記録するもの

- 合格しなかった手順の番号、見たもの、サーバーのログ（秘密を除く）。
- 5-7 の同時開始のずれ（取れた場合）。
- この手順で確かめられなかったもの（実機のキー入力、egui の窓の見た目、Windows / macOS）。

## 10. できないこと（確かめなくてよい）

CN / HCN の部屋、レート戦、5/9/10/14KEY、シリーズ戦（`all_picks` / `first_to` / `bo2`）、観戦、チャット、強制終了の投票、
ホストによるキックや解散・ホストの移譲、公開ルームの一覧、Arena oraja との対戦は、このフォークの Arena では扱いません。
詳しくは [ARENA.md](ARENA.md) の「できないこと」を見てください。
