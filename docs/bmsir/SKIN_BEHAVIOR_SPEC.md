## 1. 数値 378 / 379（J-1）

LR2oraja Endless Dream（ED）で足された数値で、Arena oraja にも入っています。
番号はスキンの数値（NUMBER）の番号です。LR2 CSV の `#SRC_NUMBER` の参照番号、JSON の `value` の `ref`、
Lua の `main_state.number(番号)` のどれからでも同じ値になります。

### 378：スコアの日時

| 項目 | 動き |
|---|---|
| 返す値 | 画面が持っている「スコア」の記録にある日時。Unix 秒（1970-01-01 からの秒）を 32 ビットの整数にしたもの |
| 選曲画面 | カーソルの曲の、保存済みのスコアの記録の日時 |
| リザルト画面 | 今回のプレイの記録の日時（下の説明） |
| プレイ画面 | プレイ中のスコア（まだ保存していない）の日時。保存前なので 0 |
| 記録が無いとき | **0** を返す（「表示しない」の値ではない） |

保存済みのスコアの記録の日時は、**その譜面のスコアを保存するたびに、保存した時刻で上書き**されます。
ベストを更新しなかったプレイでも、プレイ回数を足して保存する時に日時は新しくなります。
つまり選曲画面の 378 は「ベストを出した日時」ではなく「**最後にスコアを保存したプレイの日時**」です。

リザルト画面では、画面に入った時点で今回のスコアを保存し、その時刻を今回の記録の日時にも入れます。
保存しないプレイ（オートプレイ、リプレイ、練習、試遊など）では今回の記録に日時が入らないため 0 です。
コース（段位）のリザルトの日時の入り方は確かめていません（未確認）。

表示：

- 数字の部品で 378 を出すと、記録が無い曲では「0」が表示されます（数字が消えるのではない）。
- Lua からは 0 または Unix 秒がそのまま返ります。日時の形にするのはスキン側です。
- 2038 年を過ぎる日時は 32 ビットに収まりません。その時の元のプレイヤーの値は確かめていません（未確認）。

### 379：落ちた小節

| 項目 | 動き |
|---|---|
| 値が入る時 | プレイ中にゲージが 0 になった最初の瞬間 |
| 返す値 | 落ちた時刻までに通った譜面の位置を、**4/4 拍子の 1 小節を 1 とする単位**で数え、小数を切り捨てた整数。**0 始まり** |
| 値が無いとき | **-1** を返す（「表示しない」の値ではない） |
| 値が消える時 | 次のプレイ（コースなら次の曲）を始める時。選曲画面で曲を決めた時にも消える |

数え方の詳しい説明：

- 位置は「譜面の先頭からの、4/4 拍子 1 小節分を 1 とした長さ」です。
  BMS の各小節は、`#xxx02`（小節の長さ）で長さを変えた分だけ伸び縮みして積み上がります。
  たとえば小節 000 の長さが 0.5 なら、小節 001 の先頭は位置 0.5 です。
- 落ちた時刻より前（同じ時刻を含む）で最後にある譜面上の時点の位置を取り、小数を切り捨てます。
  小節線の時点も譜面上の時点に含まれます。
- そのため、**すべての小節が 4/4 拍子の譜面では、BMS の小節番号（000 から始まる番号）と同じ値**になります。
  最初の小節（000）で落ちれば 0 です。
- 小節の長さを変えている譜面では、小節番号とずれます。
  例：小節 000〜003 の長さがすべて 0.5 の譜面で小節 003 の途中で落ちると、位置は 1.5〜2.0 の間なので 1 になります（小節番号は 3）。
- bmson は、譜面の位置（パルス）を「4 拍分のパルス数」で割った値を位置として使います。小節線の置き方とは関係しません。
- 譜面の最初の時点より前に落ちることは普通ありませんが、その場合は 0 です。

値が入る条件：

- ゲージが 0 になった時に記録します。FAILED で終わるかどうかとは別です。
  ゲージの自動切り替えの設定が「続行」や「SURVIVAL から GROOVE へ」の時は、ゲージが 0 になってもプレイが続きますが、379 には値が入ります。
  そのままクリアしたリザルトでも 379 は値を持ちます。
- ゲージの自動切り替えが「BEST CLEAR」「下へ選択」の時は、この記録の処理を通らないため 379 は -1 のままです。
- 一度記録したら、そのプレイの中では上書きしません（最初に 0 になった時の位置のまま）。
- 値はプレイ画面・リザルト画面・選曲画面のどこからでも読めます。プレイ中も、落ちた直後から値が見えます。

表示：

- 数字の部品で -1 を出すと、マイナス用の画像が無い（10 マス・11 マス）部品では「1」と表示されます（符号を捨てて絶対値を出すため）。
  マイナス用の画像がある（24 マス）部品では「-1」です。
- スキンが「落ちていない時は消す」ようにしたい時は、スキン側で条件を付けている、と考えられます。LITONE がどう書いているかは確かめていません（未確認）。

## 2. LR2 CSV の共通の決まり

LR2 のスキン（`.lr2skin` のヘッダーと `.csv` の本体）を、元のプレイヤーがどう読むかです。

### 2.1 行と列

- 文字コードは Shift_JIS（MS932）として読みます。
- `#` で始まる行だけが命令です。それ以外の行（`//` のコメント、空行など）は読み飛ばします。
- 行はカンマで区切ります。1 列目（0 番目）が命令の名前、2 列目から後が値です。
  以下、列の番号は「命令の名前を 0 番」として数えます。
- 命令の名前の大文字・小文字は区別しません。知らない命令は何も言わずに読み飛ばします。
- 同じファイルの中で、上から順に読みます。`#INCLUDE,ファイル` は、その場所でそのファイルを上から読みます。

### 2.2 数の読み方、空欄、`--`

- 1〜21 番目の列は整数として読みます。
- 読む前に、`!` を `-` に置き換え、空白を取り除きます。`!5` は -5 です。
- 整数として読めない値（空欄、`--`、文字、小数など）は **0** になります。警告は出しません。
  たとえば `#DST_IMAGE,0,0,10,20,,,` のように w・h が空欄なら、w・h は 0 です。
- 列が足りない（行が短い）時も、足りない列は 0 です。
- 22 番目より後の列は「オフセットの番号」として読みます（2.6）。
- `--` を特別な意味に使うのは、ポップンキャラの `.chp` ファイルだけです（3 章）。CSV の中の `--` は 0 です。

### 2.3 `#IF` と分岐

- `#IF,a,b,c,...` は、並べた番号の**すべて**が成り立つ時に、次の `#ELSEIF` / `#ELSE` / `#ENDIF` までの行を読みます。空欄の列は無視します。
- 番号の前に `-` または `!` を付けると「成り立たない時」です。
- 番号の判定：
  1. スキン設定（`#CUSTOMOPTION` で選ぶ番号、`#SETOPTION` で決めた番号）にある番号なら、選ばれているか（1）・いないか（0）で決めます。
  2. スキン設定に無い番号なら、その画面の状態の条件（OPTION の番号）を、**スキンを読み込んだ瞬間に 1 回だけ**調べます。
     その後に状態が変わっても、読み込み直すまで分岐は変わりません。
  3. どちらにも無い番号は成り立たないとします。
- `#ELSEIF` は、それまでの `#IF` / `#ELSEIF` が成り立たなかった時だけ調べます。`#ELSE` も同じです。
- **入れ子にはなりません。** `#IF` の中に `#IF` を書くと、内側の `#IF` が外側の状態を上書きし、内側の `#ENDIF` で分岐が全部終わります。
  BMZ は入れ子を扱いますが、元のプレイヤーでは入れ子に書いたスキンの動きが違います（LR2 本体は未確認）。
- `#SETOPTION,番号,値` は、分岐で読む場所にある時だけ効きます。値が 1 以上なら「選ばれている」、0 以下なら「選ばれていない」になります。

### 2.4 ヘッダー（`.lr2skin`）

| 命令 | 列 | 動き |
|---|---|---|
| `#INFORMATION` | 1 種類, 2 名前, 3 作者 | 種類は画面の種類の番号（下の表）。プレイの種類では、元のプレイヤーが「BGA Size」「Ghost」「Score Graph」「Judge Detail」の設定と、4 つのオフセット（全体・ノーツ・判定・判定詳細）を自動で足す |
| `#RESOLUTION` | 1 番号 | 0＝640×480、1＝1280×720、2＝1920×1080、3＝3840×2160。省略時の扱いは元のプレイヤーの別の所で決まる（未確認） |
| `#CUSTOMOPTION` | 1 名前, 2 最初の番号, 3 以降 項目の名前 | 項目の数だけ番号を割り当てる（最初の番号、+1、+2、…）。空欄の項目は数えない |
| `#CUSTOMFILE` | 1 名前, 2 パス（`*` を含む）, 3 既定のファイル名 | パスの `LR2files\Theme` はスキンのフォルダに読み替える |
| `#CUSTOMOFFSET` | 1 名前, 2 オフセットの番号, 3〜8 x・y・w・h・r・a を設定できるか | 3〜8 は 1 以上で「設定できる」。省略は「設定できる」 |
| `#CUSTOMOPTION_ADDITION_SETTING` | 1〜4 | 自動で足す 4 つの設定（BGA Size, Ghost, Score Graph, Judge Detail の順）のうち、0 と書いたものを外す |

画面の種類の番号は、beatoraja の番号と同じです（0〜4 プレイ、5 選曲、6 決定、7 リザルト、15 コースリザルト など。BMZ の `docs/skin.md` の「Skin Type」と同じ）。

### 2.5 `#SRC_*` の共通の列

ほとんどの `#SRC_*` は、1〜10 番目の列の意味が同じです。

| 列 | 名前 | 意味 |
|---:|---|---|
| 1 | index | 命令ごとの番号（ノーツのレーン、判定の 1P/2P など）。使わない命令もある |
| 2 | gr | `#IMAGE` で読んだ画像の番号（0 から、`#IMAGE` を書いた順）。100 以上は特別な画像（下の表） |
| 3 | x | 画像の中の切り出し位置（左） |
| 4 | y | 画像の中の切り出し位置（上） |
| 5 | w | 切り出す幅。**-1 なら画像の幅全体** |
| 6 | h | 切り出す高さ。**-1 なら画像の高さ全体** |
| 7 | div_x | 横の分割数。0 以下は 1 |
| 8 | div_y | 縦の分割数。0 以下は 1 |
| 9 | cycle | アニメーション 1 周の時間（ms） |
| 10 | timer | アニメーションの起点にするタイマーの番号 |
| 11〜 | | 命令ごとの値（2.8） |

特別な画像の番号（`#SRC_IMAGE` の gr）：

| gr | 画像 |
|---:|---|
| 100 | 曲の STAGEFILE |
| 101 | 曲の BACKBMP |
| 102 | 曲の BANNER |
| 110 | 黒一色 |
| 111 | 白一色 |

`#IMAGE` で読めなかった画像の番号を指すと、その部品は作られません（警告だけ出ます）。
`#IMAGE` に動画（mp4 など）を書いた場合、`#SRC_IMAGE` は動画を流す部品になります。

### 2.6 分割（div_x / div_y）とマスの順番

- 切り出した範囲（x, y, w, h）を、横に div_x 個、縦に div_y 個の同じ大きさのマスに分けます。
  1 マスの大きさは「w を div_x で割った整数」「h を div_y で割った整数」です（割り切れない分は捨てます）。
- **マスの番号は、左上から右へ数え、行の終わりで次の行の左へ移ります**（横書きの読み方）。
  例：div_x=4, div_y=2 なら、上の行が 0, 1, 2, 3、下の行が 4, 5, 6, 7 です。
- ふつうの画像部品では、マスはアニメーションのコマです。cycle の時間でマス 0 から順に等しい時間ずつ出し、最後の後はマス 0 に戻ります。
- cycle が 0 なら、最初のマス（0 番）だけを出します。
- 数字・ゲージ・選曲バーのグラフなど、マスを「種類」に使う部品は、決まった数のマスを 1 組にして並べます。
  組が 2 つ以上あれば、組がアニメーションのコマになります（各部品の章）。

### 2.7 `#DST_*` の共通の列

ほとんどの `#DST_*` は列の意味が同じです。1 つの部品に `#DST_*` を何行も書くと、行がアニメーションの「キー」になります。

| 列 | 名前 | 意味 |
|---:|---|---|
| 1 | index | 命令ごとの番号（多くは無視） |
| 2 | time | このキーの時刻（ms）。タイマーが入ってからの経過時間 |
| 3 | x | 置く位置（左） |
| 4 | y | 置く位置（上） |
| 5 | w | 幅 |
| 6 | h | 高さ |
| 7 | acc | キーの間の動き方（下の表） |
| 8 | a | 不透明度 0〜255 |
| 9 | r | 赤 0〜255（画像に掛ける色） |
| 10 | g | 緑 0〜255 |
| 11 | b | 青 0〜255 |
| 12 | blend | 重ね方（下の表） |
| 13 | filter | 1 なら拡大縮小をなめらかにする |
| 14 | angle | 回転（度）。反時計回りが + |
| 15 | center | 回転・拡大の中心（下の表） |
| 16 | loop | ループの開始時刻（下の説明） |
| 17 | timer | 表示の起点にするタイマーの番号 |
| 18 | op1 | 表示の条件（OPTION の番号。- で否定） |
| 19 | op2 | 同上 |
| 20 | op3 | 同上 |
| 21〜 | offset | オフセットの番号（いくつでも並べてよい） |

**1 行目（最初に書いたキー）だけで決まる値**：acc、blend、filter、center、loop、timer、op1〜op3。
正確には「0 以外の値を最初に書いたキーの値」が使われ、後のキーで違う値を書いても変わりません。
（op1〜op3 は、0 以外の条件を 1 つでも持つ最初のキーの 3 つ組が使われます。）
2 行目以降で意味があるのは、time・x・y・w・h・a・r・g・b・angle です。

キーの並び：

- キーは time の小さい順に並べ直されます。書く順番は自由です。
- 同じ時刻のキーが 2 つあると、後に書いた方が後ろに入ります（どちらが使われるかの細部は未確認）。

位置の変換：

- スキンの解像度（`#RESOLUTION`）から画面の解像度へ、x・w は横の比、y・h は縦の比で拡大縮小します。
- `#DST_IMAGE`（と `#DST_PM_CHARA_IMAGE`、`#DST_BAR_GRAPH`）は、w が負なら「x を w だけ左にずらし、w を正にする」、h が負なら「y を h だけ上にずらし、h を正にする」と直します。
  **画像は反転しません**。ほかの `#DST_*`（数字・文字など）はこの直しをしません。
  LR2 本体で w・h が負の時に画像が反転するかは未確認です。

acc（キーの間の動き方）：

| acc | 動き |
|---:|---|
| 0 | 一定の速さ（直線） |
| 1 | だんだん速く（進み具合を 2 乗） |
| 2 | だんだん遅く |
| 3 | 動かさない。次のキーの時刻まで、前のキーの値のまま |

位置・大きさ・色・不透明度・回転のすべてに同じ動き方を使います。回転は整数（度）に切り捨てます。

blend（重ね方）：

| blend | 動き |
|---:|---|
| 0, 1 | ふつう（不透明度で重ねる） |
| 2 | 加算 |
| 3 | 減算のつもりの値。ただし元のプレイヤーのコードの並びでは、描く前にふつうの足し方へ戻しているため、加算と同じに見える（未確認） |
| 4 | 乗算 |
| 9 | 色の反転 |

center（回転・拡大の中心）。テンキーの並びと同じです：

| center | 中心 |
|---:|---|
| 0, 5 | 真ん中 |
| 1 | 左下 |
| 2 | 下の真ん中 |
| 3 | 右下 |
| 4 | 左の真ん中 |
| 6 | 右の真ん中 |
| 7 | 左上 |
| 8 | 上の真ん中 |
| 9 | 右上 |

### 2.8 タイマー・表示の条件・ループ

タイマー（17 列目）：

- 0 は「タイマー無し」で、画面に入ってからの時間で動きます。
- 1 以上は、その番号のタイマーが入ってからの時間で動きます。
  **タイマーが切れている間は、部品を描きません。**
- 負の番号はタイマー無しと同じです（未確認：コード上は 1 以上だけをタイマーとして扱う）。
- タイマーの番号は beatoraja と同じ番号表です（BMZ の `docs/skin.md` の番号表と同じ範囲）。ポップンキャラのタイマーは 3 章。

表示の条件（18〜20 列目）：

- 3 つすべてが成り立つ時だけ描きます。0 は「条件無し」です。同じ番号を 2 回書いても 1 回と同じです。
- 画面の状態の条件（OPTION の番号）は毎フレーム調べます。
- スキン設定の番号（`#CUSTOMOPTION` の番号）は、スキン設定の選び方で決まります。

ループ（16 列目）：

| loop | 動き |
|---|---|
| -1 | ループしない。最後のキーの時刻を過ぎたら**描かない** |
| 0 | 最初から最後のキーまでを繰り返す（最後のキーの時刻が 0 なら、ずっと 1 つ目のキーのまま） |
| 1 以上で、最後のキーの時刻より小さい | 最後のキーの時刻を過ぎたら、loop の時刻へ戻って、loop〜最後のキーの間を繰り返す |
| 最後のキーの時刻と同じ | 最後のキーの状態で止まる |

- 最初のキーの時刻より前は描きません（タイマーの起点からの時間で比べます）。

オフセット（21 列目から）：

- 書いた番号のオフセット（スキン設定の `#CUSTOMOFFSET` や、プレイヤーが設定したレーンカバー等）の値を足します。
- x・y・w・h を足します。x・y には「オフセットの x から w の半分を引いた値」「y から h の半分を引いた値」を足すので、w・h を増やすと真ん中を中心に広がります（一部の部品は w・h だけを足す）。
- 回転（r）は角度に、不透明度（a）は 0〜255 の値として足し、0〜1 に収めます。

### 2.9 透過色（黒抜きなど）

- 元のプレイヤー（Arena oraja）の LR2 CSV の読み込みには **`#TRANSCOLOR` の処理がありません**。
  `#TRANSCOLOR` は知らない命令として読み飛ばされ、画像は画像自身の透明度（PNG のアルファなど）だけで描かれます。
  アルファを持たない BMP などは、黒も含めてそのまま不透明に描かれます。
- BMZ は `#TRANSCOLOR` を扱います（調査の表）。LR2 本体の動き（既定で黒を抜くかどうかなど）は未確認です。
  BMZ の今の動きを元のプレイヤーに合わせて消すかどうかは、2 段目の見比べで決めてください。
- 例外は、ポップンキャラの画像です（3 章）。

### 2.10 主な部品の 11 番目からの列

調査の上位に関係する部品だけを書きます。

`#SRC_NUMBER`（数字）：

| 列 | 意味 |
|---:|---|
| 11 | 数値の番号 |
| 12 | 揃え：0＝右詰め、1＝左詰め、2＝中央 |
| 13 | 桁数 |
| 14 | 0 の埋め方（24 マスの時だけ使う。下の表） |
| 15 | 字の間の隙間 |

- マスの数（div_x × div_y）が 10 未満なら、部品を作りません。
- マスの数によって、マスの意味が変わります：

| マスの数 | 1 組 | 1 組の中身（マスの番号） |
|---|---|---|
| 24 の倍数 | 24 マス | 0〜9＝数字（＋用）、10＝裏ゼロ（＋用）、11＝符号（＋用）、12〜21＝数字（－用）、22＝裏ゼロ（－用）、23＝符号（－用） |
| 10 の倍数（24 の倍数でない） | 10 マス | 0〜9＝数字 |
| それ以外 | 11 マス | 0〜9＝数字、10＝空いた桁に出す画像（裏ゼロ） |

- 組が 2 つ以上あれば、組がアニメーションのコマになります（cycle・timer）。
- 24 マスの時は、桁数に 1 を足します（符号の分）。
- 0 の埋め方：10 マスは「空いた桁は何も描かない」、11 マスは「空いた桁に 10 番のマスを描く」で固定です。
  24 マスは 14 列目の値（空欄なら 2）：0＝何も描かない、1＝0 を描く、2＝裏ゼロを描く。
- 値が「表示しない」の値（整数の最小値・最大値）なら、何も描きません。
- 桁数を超える値は、上の桁を捨てます（1234 を 3 桁で出すと 234）。
- 負の値：－用のマスがある（24 マス）時は－用の組で描きます。無い時は、符号を捨てて絶対値を描きます。
- 24 マスの時は、正の値でも＋用の組の 11 番（符号）を描きます。
  0 の埋め方が 0 の時は数字のすぐ左に、1・2 の時はいちばん左の桁に符号を置きます。
- 揃え：空いた桁は左側にできます。0 は空いた桁をそのまま残す（数字は右に寄る）、1 は空いた桁の分だけ左へずらす（数字は左に寄る）、2 はその半分だけずらします。

`#SRC_GROOVEGAUGE` / `#SRC_GROOVEGAUGE_EX` は 6 章、`#SRC_BAR_GRAPH` は 4 章、ポップンキャラの命令は 3 章です。

ほかの部品（ノーツ、判定、文字、ボタン、スライダーなど）の列は、この文書では書いていません。
BMZ は調査の時点でこれらを扱っており、止まっている項目ではないためです。

## 3. ポップンキャラ（R-1・J-3・J-4）

ポップンキャラ（PMS のキャラクター、以下「キャラ」）は、`.chp` ファイルとその画像から作る部品です。
LR2 CSV では `#DST_PM_CHARA_*` / `#SRC_PM_CHARA_IMAGE`、JSON・Lua では `pmchara` で使います。
キャラの組み立て方（`.chp` の読み方、アニメーション、透過色）は、LR2 CSV でも JSON でも同じです。

### 3.1 LR2 CSV の命令

| 命令 | 列（1 番目から） | 動き |
|---|---|---|
| `#DST_PM_CHARA_1P` | x, y, w, h, color, offset, folderpath | プレイ用。判定に合わせて動く 1P 側のキャラ |
| `#DST_PM_CHARA_2P` | x, y, w, h, color, offset, folderpath | プレイ用。判定に合わせて動く 2P 側（相手）のキャラ |
| `#DST_PM_CHARA_ANIMATION` | x, y, w, h, color, animationtype, timer, op1, op2, op3, offset, folderpath | 判定と関係なく、決めたモーションを 1 つ出す |
| `#SRC_PM_CHARA_IMAGE` | color, type, folderpath | キャラの静止画（背景・名前・顔など）を 1 枚の画像部品として作る |
| `#DST_PM_CHARA_IMAGE` | `#DST_IMAGE` と同じ | 直前の `#SRC_PM_CHARA_IMAGE` の置き場所。`#DST_IMAGE` と同じ動き |

共通：

- x, y, w, h はキャラを置く枠です。w・h が負なら、`#DST_IMAGE` と同じく枠を正の向きに直します（反転はしない）。
- color：1＝1P の色、2＝2P の色。1・2 以外は 1 として扱います。
- offset：オフセットの番号（1 つ）。モーションの最後のキーにだけ付きます。
- folderpath：`.chp` ファイルのパス、または `.chp` があるフォルダのパス。
  - `.chp` のファイルがあれば、それを使います。
  - `.chp` で終わるパスでファイルが無ければ、そのパスのフォルダの中の最初の `.chp` を使います。
  - それ以外はフォルダとみなし、中の最初の `.chp` を使います（「最初」の順番はファイルシステムの並び順で、決まっていない）。
  - `LR2files\Theme` はスキンのフォルダに読み替えます。`#CUSTOMFILE` の選択も効きます。
- `#DST_PM_CHARA_1P` / `_2P` / `_ANIMATION` は、1 行で部品を作り終えます（`#SRC` の行は要りません）。
  1 つのキャラから、モーションごと・画像の層ごとに複数の部品ができます。

`#DST_PM_CHARA_ANIMATION` の animationtype：

| 値 | モーション |
|---:|---|
| 0 | NEUTRAL |
| 1 | FEVER |
| 2 | GREAT |
| 3 | GOOD |
| 4 | BAD |
| 5 | FEVERWIN |
| 6 | WIN |
| 7 | LOSE |
| 8 | OJAMA |
| 9 | DANCE |

0〜9 以外なら何も作りません。timer・op1〜op3 は、そのモーションの部品の表示の起点と条件になります（2.8 と同じ意味）。

`#SRC_PM_CHARA_IMAGE` の type：

| 値 | 画像 | 切り出す範囲 |
|---:|---|---|
| 0 | キャラの背景 | `.chp` の座標の定義の 01 番 |
| 1 | 名前の画像 | `.chp` の座標の定義の 00 番 |
| 2 | 顔（上半身） | `#CharFaceUpperSize`（既定は 0, 0, 256, 256） |
| 3 | 顔（全体） | `#CharFaceAllSize`（既定は 320, 0, 320, 480） |
| 4 | キャラのアイコン（選曲用） | `#SelectCG` の画像全体 |

0〜4 以外なら何も作りません。顔とアイコンは、画像が無ければ何も作りません。
2P の色の時は、`#CharFace2P` / `#SelectCG2P` があればそちらを使います。

### 3.2 `.chp` ファイルの読み方

- 文字コードは Shift_JIS。`#` で始まる行だけを読みます。
- 列は**タブ**で区切ります。空の列は詰めます。`/` で始まる列から後と、`//` から後は捨てます。
- 命令の名前の大文字・小文字は区別しません。

| 命令 | 値 | 意味 |
|---|---|---|
| `#CharBMP` | ファイル名 | `#Pattern` と `#Layer` に使う画像（1P の色） |
| `#CharBMP2P` | ファイル名 | 同上（2P の色） |
| `#CharTex` | ファイル名 | `#Texture` に使う画像（1P の色） |
| `#CharTex2P` | ファイル名 | 同上（2P の色） |
| `#CharFace` / `#CharFace2P` | ファイル名 | 顔の画像 |
| `#SelectCG` / `#SelectCG2P` | ファイル名 | アイコンの画像 |
| `#Size` | 幅, 高さ | キャラの座標の基準の大きさ（3.4） |
| `#Anime` | ms | `#Frame` の無いモーションの 1 コマの時間。既定 100 |
| `#Frame`（綴りの誤り `#Flame` も同じ） | モーション, ms | そのモーションの 1 コマの時間 |
| `#Loop` | モーション, コマ番号 | ループの開始（3.5） |
| `#xx`（2 文字） | x, y, w, h | 座標の定義。xx は 36 進数（0〜9, A〜Z。大文字・小文字は同じ）で 00〜ZZ（0〜1295） |
| `#CharFaceUpperSize` / `#CharFaceAllSize` | x, y, w, h | 顔の切り出し範囲 |
| `#Pattern`（綴りの誤り `#Patern` も同じ） | モーション, 4 つの文字列 | アニメーション。いちばん下の層 |
| `#Texture` | 同上 | アニメーション。真ん中の層 |
| `#Layer` | 同上 | アニメーション。いちばん上の層 |

- 画像のファイル名は、`.chp` のあるフォルダからの相対パスです（`\` は `/` に読み替え）。
- 1 コマの時間が 1 未満なら 100 にします。
- 座標の定義の値が 4 つそろわない行は無視します。

### 3.3 色（1P / 2P）と、出さない場合

- `#CharBMP` が無ければ、キャラは何も作りません。
- color が 2 で、`#CharBMP2P` があり、かつ「`#Texture` が無いか、`#CharTex2P` がある」時だけ 2P の色にします。それ以外は 1P の色です。
- 1P の色で、`#Texture` があるのに `#CharTex` が無ければ、何も作りません。
- 層は `#Pattern`（`#CharBMP`）→ `#Texture`（`#CharTex`）→ `#Layer`（`#CharBMP`）の順に作り、後のものが上に重なります。
  同じ層の中では、`.chp` に書いた順です。

### 3.4 アニメーションの行（`#Pattern` / `#Texture` / `#Layer`）

行の形：`#Pattern<TAB>モーション<TAB>画像<TAB>位置<TAB>不透明度<TAB>回転`

4 つの文字列は、どれも「2 文字で 1 コマ」です。文字列の中の英数字と `-` 以外の文字は取り除いてから読みます。

| 文字列 | 2 文字の意味 |
|---|---|
| 画像（必須） | 座標の定義の番号（36 進数）。そのコマで出す画像の範囲 |
| 位置（省略可） | 座標の定義の番号（36 進数）。そのコマでキャラを置く範囲（`#Size` の大きさの中での位置） |
| 不透明度（省略可） | 16 進数 00〜FF |
| 回転（省略可） | 16 進数 00〜FF。360 ÷ 256 を掛けて度にし、四捨五入 |

- 画像の文字列が空か奇数の長さなら、その行は使いません。
- 位置・不透明度・回転は、空か、画像の文字列と同じ長さでなければ、その行は使いません。
- 画像の番号が座標の定義に無い（幅か高さが 0）コマは、透明（何も描かない）コマです。
- 位置が省略されたコマは、キャラの枠全体（`#Size` の大きさ全体）に置きます。不透明度の既定は 255、回転の既定は 0 です。

置く場所：

- 位置の定義（x, y, w, h）は、`#Size` の幅・高さを「キャラの枠」の幅・高さに合わせて拡大縮小します。
  つまり、`#Size` が 300×400 で枠が 150×200 なら、位置の定義はすべて半分になります。
- キーの間は動かしません（2.7 の acc 3）。重ね方はふつう（blend 1）です。

### 3.5 時間、ループ

- 1 つのモーションの 1 周の時間は「1 コマの時間 × コマの数」です。
- `#Loop` の値を n とすると、コマ 0〜n は最初の 1 回だけ出し、そのあと コマ n+1〜最後 を繰り返します。
  - 既定は -1 で、全部のコマを繰り返します。
  - n が「コマの数 - 1」以上なら、「コマの数 - 2」にします（最後の 1 コマは必ず繰り返しに入る）。
  - n が -1 より小さければ -1 にします。
- 画像のコマ（どの範囲の画像を出すか）は、その区間の時間を等しく分けて切り替えます。位置・不透明度・回転は、コマごとのキーで決まります。

### 3.6 `--`（間のコマを補う）

位置・不透明度・回転の文字列に `--` を書くと、その前後の値の間を等しい間隔で埋めます。

- 位置：`--` が続く区間の前の、最後に書いたコマの位置（範囲）と、区間の後の最初のコマの位置の間を、x・y・w・h それぞれ直線で埋めます。
  区間の前に書いたコマが無ければ、前の値は「枠全体（0, 0, `#Size` の幅, 高さ）」です。
  間の値は整数で、端数は切り捨てます（0 の方へ）。
  例：`01----02` は、コマ 1 が 01 の範囲、コマ 2・3 が 01 と 02 の間を 3 等分した 1/3・2/3 の範囲、コマ 4 が 02 の範囲です。
- 不透明度・回転：同じように前後の値の間を埋めます。区間の前に値が無ければ、前の値は **0** です（不透明度でも 255 ではありません）。
- 画像の文字列の `--` は、補う対象ではありません（その 2 文字は 36 進数として読まれ、座標の定義に無ければ透明なコマになります）。
- **`--` が文字列の最後まで続くと（後ろの値が無いと）、そのキャラの読み込みがそこで止まります。**
  それまでに作った部品は残り、残りの行・層は作られません。

`--` がある時のコマの細分化：

- 位置・不透明度・回転のどれかに `-` が 1 つでもあり、1 コマの時間が 17 ms 以上なら、1 コマを細かく分けて動きをなめらかにします。
- 分ける数は「1 コマの時間を割り切れて、分けた 1 つの時間が 17 ms 未満になる、いちばん小さい数」です。
  例：1 コマ 100 ms → 100 を割り切れて 100÷k < 17 になる最小の k は 10 なので、10 ms ずつ 10 個に分けます。
  1 コマ 51 ms → 51÷3 = 17 は 17 未満ではないので、k は 17（3 ms ずつ）です。
- 分ける時は、位置・不透明度・回転の各 2 文字（`--` も含む）を k 回ずつ繰り返してから、上の `--` の埋め方をします。
  そのため、書いた値のコマは k 個の間止まり、`--` の区間は k 倍の細かさで動きます。
- 画像の文字列は分けません。画像の切り替えは元のコマの時間のままです。
- `#Loop` の位置も k 倍のコマに合わせます。

### 3.7 透過色（右下の 1 画素）

- キャラの画像は、**画像のいちばん右下の 1 画素と、色と透明度がまったく同じ画素**を透明にします（黒とは限りません）。
- 対象：`#CharBMP`、`#CharBMP2P`、`#CharTex`、`#CharTex2P`、`#CharFace`、`#CharFace2P`。
- 対象外：`#SelectCG` / `#SelectCG2P`（アイコン）は透明にしません。
- 1 枚の画像には 1 回だけ行います。近い色（少しだけ違う色）は透明にしません。
- 画像がもともと持つ透明な画素は、そのまま透明です。

### 3.9 タイマー 900〜909（J-3 の答え）

ポップンキャラのタイマーは、**ふつうのタイマーと同じ番号表**にあります。
スキンは、ほかのタイマーと同じように DST の timer（LR2 CSV の 17 列目、JSON の `timer`、Lua の `main_state.timer(番号)`）で参照できます。

| 番号 | 名前 | 動き |
|---:|---|---|
| 900 | 1P NEUTRAL | 下の流れ |
| 901 | 1P FEVER | 同上 |
| 902 | 1P GREAT | 同上 |
| 903 | 1P GOOD | 同上 |
| 904 | 1P BAD | 同上 |
| 905 | 2P NEUTRAL | 同上 |
| 906 | 2P GREAT | 同上 |
| 907 | 2P BAD | 同上 |
| 908 | 曲の終わり（MUSIC_END） | 曲が終わって FINISHED に移る時に入る。キャラだけのタイマーではない |
| 909 | DANCE | プレイ中は毎フレーム「入っている」状態にする（最初に入った時刻のまま）。曲が終わる時に切る |

タイマーの流れ（プレイ画面）：

1. 読み込み中から、900 と 905 を入れます（まだ入っていなければ）。
2. 毎フレーム、900 について次を調べます。
   - 900 が入っていて、900 の経過時間が「NEUTRAL の 1 周の時間」以上で、
     かつ経過時間を 1 周の時間で割った余りが 17 ms 未満（＝ NEUTRAL がちょうど 1 周し終わった所）であり、
   - NEUTRAL が始まった時から判定済みのノーツの数が変わっていて、判定が 1 つ以上ある時：
     いちばん新しい判定で次のタイマーを入れ、900 を切ります。
     - PGREAT・GREAT：ゲージが満タンなら 901（FEVER）、そうでなければ 902（GREAT）
     - GOOD：903（GOOD）
     - それ以外（BAD・POOR・空 POOR）：904（BAD）
3. 905 も同じ調べ方をし、いちばん新しい判定が PGREAT・GREAT・GOOD なら 907（2P BAD）、それ以外なら 906（2P GREAT）を入れて 905 を切ります。
4. 901〜904、906、907 のうち入っているものが、そのモーションの 1 周の時間を過ぎたら、それを切り、NEUTRAL（1P なら 900、2P なら 905）を入れ直します。この時の判定済みのノーツの数を覚えます。
5. 曲が終わる時に 900〜907 と 909 を切り、908 を入れます。

- 「1 周の時間」は、そのキャラの `.chp` から作ったモーションの「1 コマの時間 × コマの数」です。
  プレイ用のキャラ（`_1P` / `_2P`）を作った時に、モーションごとに覚えます。作られていないモーションの 1 周の時間は 1 ms です。
- 同じ画面に複数のプレイ用キャラを置いた時は、後から作ったキャラの 1 周の時間で上書きされます。
- 「判定」の区別は、PGREAT＝1、GREAT＝2、GOOD＝3、それ以外＝4 以上、という順番で決まります。
- 練習モードで設定の画面に戻った時は、900〜909 をいったん全部切り、900・905 を入れ直します。

## 4. 選曲バーの `BAR_GRAPH` type 1（R-3）

選曲画面の、フォルダのバーに出す棒グラフです。type 0 はクリアランプの分布（11 種類）、type 1 はスコアランクの分布（28 種類）です。

### 4.1 命令

| 命令 | 列 | 動き |
|---|---|---|
| `#SRC_BAR_GRAPH` | 共通の SRC の列（2.5）。1 番目（index）が type | type が 0 なら 11 種類、0 以外なら 28 種類として、マスを分ける |
| `#DST_BAR_GRAPH` | 共通の DST の列（2.7） | 位置は**バーの左上からの相対位置**。w・h が負なら正の向きに直す |

- 切り出し・分割は共通の決まり（2.6）です。マスの番号は左上から右へ、行の終わりで次の行です。
- **マスの並び**：最初の 28 マスがアニメーションの 1 コマ目の「種類 0, 1, 2, …, 27」、次の 28 マスが 2 コマ目の「種類 0〜27」、…です。
  つまり「種類 k の c コマ目」はマス番号 c × 28 + k です。type 0 なら 28 の代わりに 11 です。
- コマの数は「マスの数 ÷ 28（または 11）」で、cycle・timer で切り替えます。
- `#DST_BAR_GRAPH` は、`#SRC_BAR_GRAPH` で作ったグラフに付きます。
  グラフは 1 つの選曲スキンに 1 つで、後から書いた `#SRC_BAR_GRAPH` が前のものを置き換えます。

### 4.2 28 種類の意味（スコアランクを 27 等分）

フォルダの中の譜面ごとに、ベストの EX スコアの率（EX スコア ÷ 最大 EX スコア）で種類を決めます。
**率を 27 等分した何番目か**（小数切り捨て）が種類の番号です。率 100% だけが 27 です。

| 種類 | 率の範囲 | 一般的なランク |
|---:|---|---|
| 0 | 0 以上 1/27 未満。**未プレイの譜面とノーツ数 0 の譜面もここ** | F |
| 1〜5 | k/27 以上 (k+1)/27 未満 | F |
| 6〜8 | 同上 | E |
| 9〜11 | 同上 | D |
| 12〜14 | 同上 | C |
| 15〜17 | 同上 | B |
| 18〜20 | 同上 | A |
| 21〜23 | 同上 | AA |
| 24〜26 | 同上 | AAA |
| 27 | 100%（MAX） | MAX |

ランクの区切り（AAA は 24/27＝8/9 以上、AA は 21/27 以上 …）は、beatoraja のランクの区切りと同じ位置に来ます。

元のプレイヤーが画像を持たない時に使う既定の色（参考。`#SRC_BAR_GRAPH` があればその画像を使います）：
0 は暗い灰色、1〜5 は暗い紫、6〜8 と 9〜11 は暗い青系、12〜14 は緑、15〜17 は黄緑、18〜20 は水色、21〜23 は明るい灰色、24〜26 は明るい水色、27 はさらに明るい水色。

### 4.3 数え方

- 対象は、フォルダの中の譜面です。今のキーモード（7 鍵など）と違う譜面は数えません（モードの無い譜面は数えます）。
- ベストのスコアは、今の LN モードのスコアの記録から読みます。
- スコアの記録が無い譜面は、種類 0 に数えます（クリアランプの方も「未プレイ」に数えます）。

### 4.4 描き方

- フォルダのバー（ふつうのフォルダ・表のフォルダなど）にだけ描きます。曲のバーには描きません。
- グラフの枠（DST の位置と大きさ）を、合計の譜面数に対する各種類の譜面数の割合で横に分けます。
- **左から、種類 27 → 26 → … → 0 の順に並べます**（いちばん左が MAX）。数が 0 の種類は幅 0 です。
- 各種類の幅は「枠の幅 × その種類の数 ÷ 合計」、左端は「それより前の種類の数の合計」で決まります。
- 譜面が 1 つも無いフォルダには何も描きません。
- 設定の「フォルダのランプ（folderlamp）」が切れている時は、グラフを描きません（type 0 も 1 も）。
- 高さは枠の高さのままです。

## 5. `floatvalue`（J-2）

JSON・Lua のスキンで、小数の数値を画像の数字で出す部品です。

### 5.1 項目

| 項目 | 既定 | 意味 |
|---|---|---|
| `id` | | 部品の名前 |
| `src`, `x`, `y`, `w`, `h`, `divx`, `divy` | divx・divy は 1 | 画像と分割（`value` の部品と同じ） |
| `timer`, `cycle` | 0 | アニメーション |
| `iketa` | 0 | 整数の部分の桁数 |
| `fketa` | 0 | 小数の部分の桁数 |
| `isSignvisible` | false | 符号を出すか（26 マスの時だけ効く） |
| `align` | 0 | 0＝左詰め、1＝右詰め、2＝中央 |
| `zeropadding` | 0 | 0＝空いた桁は何も描かない、1＝0 を描く、2＝裏ゼロを描く。2 より大きい値は 2 |
| `space` | 0 | 字の間の隙間 |
| `gain` | 1.0 | 値に掛ける数（率を百分率で出す時は 100 など） |
| `ref` | | 小数の値の番号（5.4） |
| `value` | | 値。文字列なら Lua の式、数なら「率の番号」（5.4） |
| `offset` | | 桁ごとの位置の調整（`value` の部品と同じ） |
| `padding` | | 読み込むが使っていない |

`value` があれば `value` を、無ければ `ref` を使います。

### 5.2 マスの意味

マスの数（divx × divy）で、1 組の大きさと中身が決まります。上から順に、割り切れる最初のものを使います。

| マスの数 | 1 組 | 中身（マスの番号） | 符号 |
|---|---|---|---|
| 26 の倍数 | 26 | 0〜9＝数字（＋用）、10＝裏ゼロ、11＝小数点、12＝符号（＋用）、13〜22＝数字（－用）、23＝裏ゼロ、24＝小数点、25＝符号（－用） | `isSignvisible` が効く |
| 24 の倍数 | 24 | 0〜9＝数字（＋用）、10＝裏ゼロ、11＝小数点、12〜23＝同じ並びの－用 | 出さない |
| 22 の倍数 | 22 | 0〜9＝数字（＋用）、10＝小数点、11〜20＝数字（－用）、21＝小数点（－用）。裏ゼロは、その組の「0」の画像を使う | 出さない |
| 12 の倍数 | 12 | 0〜9＝数字、10＝裏ゼロ、11＝小数点 | 出さない。負の値は絶対値 |
| 11 の倍数 | 11 | 0〜9＝数字、10＝小数点。裏ゼロは「0」の画像 | 出さない。負の値は絶対値 |
| それ以外 | 12 | 12 マスとして読む。12 に満たない分は組にならない（12 未満なら部品にならない見込み。未確認） | 出さない |

- 組が 2 つ以上あれば、組がアニメーションのコマになります。
- 26・24・22 マスの時、値（gain を掛けた後）が負なら－用の組で描き、0 以上なら＋用の組で描きます。

### 5.3 桁の作り方

桁数：

- iketa・fketa の負の値は 0 にします。
- iketa・fketa のどちらかが 8 以上、または合計が 8 以上の時は、fketa を 8 までにして、iketa を「8 - fketa」にします。
  （例：iketa 6・fketa 5 → iketa 3・fketa 5。iketa 3・fketa 8 → iketa 0・fketa 8）
- 描く桁の数は「符号の 1 桁（`isSignvisible` の時）＋ iketa ＋ fketa ＋ 小数点の 1 桁（fketa が 1 以上の時）」です。

値：

- 値に gain を掛け、その絶対値を使います。
- 値（または gain を掛けた値）が「表示しない」の値（小数の最小値・最大値）、無限大、非数のどれかなら、何も描きません。
  描く桁の数が 0 の時も描きません。
- 小数の部分は fketa 桁で**切り捨て**です（四捨五入しません）。
  内部の小数の誤差で、見た目より 1 小さい値になることがあります（例：1.35 を 1 桁で出すと 1.3）。
- 整数の部分が iketa 桁を超えたら、上の桁を捨てます（9999.9 を iketa 3・fketa 2 で出すと 999.90）。

並び（左から）：

- 符号の桁 → 整数の部分 → 小数点 → 小数の部分、の順です。小数点は fketa が 1 以上の時だけです。
- `zeropadding` が 1・2 の時は、整数の部分を iketa 桁ちょうどにし、空いた上の桁に「0」（1 の時）か裏ゼロ（2 の時）を描きます。
- `zeropadding` が 0 の時は、整数の部分を必要な桁数だけにし（0 なら 1 桁）、**数字を左に詰めて、空いた桁は右側にできます**。
- iketa が 0 の時は、整数の部分を描かず、小数点から始めます（0.75 → `.75`）。

符号（26 マスで `isSignvisible` の時）：

- 符号の桁には、値の絶対値が 10 の iketa 乗より小さい時に符号のマスを描きます。＋用の組なら＋の符号、－用の組なら－の符号です。
- 値が大きく、整数の部分が iketa 桁を超える時は、符号の桁に数字（はみ出した上の桁）が入ります。
- iketa も fketa も 0 なら、符号だけを描きます。

揃え：

- 空いた桁（何も描かない桁）は右側にできます。
- align 0 は空いた桁をそのまま残します（数字は左に寄る）。align 1 は空いた桁の分だけ右へずらします（数字は右に寄る）。align 2 はその半分ずらします。
- `value` の数字（整数）とは、空いた桁のできる側が逆なので、揃えの値の意味も逆です。

例（iketa 3・fketa 2・符号なし）：

| 値 | zeropadding 0 | zeropadding 1 | zeropadding 2 |
|---:|---|---|---|
| 0 | `0.00` ＋空き 2 | `000.00` | `裏裏0.00` |
| 1.5 | `1.50` ＋空き 2 | `001.50` | `裏裏1.50` |
| 12.345 | `12.34` ＋空き 1 | `012.34` | `裏12.34` |
| 123.456 | `123.45` | `123.45` | `123.45` |

例（同じ桁数で符号あり、26 マス）：1.5 → `＋1.50`＋空き 2、9999.9 → `9999.90`（符号の桁に 9）。

### 5.4 値の番号

`ref`（数）は、下の「小数の値」の表で探し、無ければ「率」の表（スライダー・バーグラフの率の番号）で探します。
`value` に数を書いた時は「率」の表だけを使います。`value` に文字列を書いた時は Lua の式として読みます。

小数の値（`ref` で使う番号。率は 0〜1 の値で、百分率で出すには gain 100）：

| 372 | duration_average | リザルト：平均の表示時間（緑数字のもと）÷ 1000 |

| 285〜289 | rival_perfect_rate 〜 rival_poor_rate | ライバルの同じ値 |

## 6. ゲージの `parts` と光り（J-7）

### 6.1 36 枚の画像の並び

ゲージは、内部で 36 枚の画像を使います。ゲージの種類ごとに 6 枚の組が 6 つあります。

組（ゲージの種類）：

| 組 | 画像の番号 | ゲージ |
|---:|---|---|
| 0 | 0〜5 | ASSIST EASY |
| 1 | 6〜11 | EASY |
| 2 | 12〜17 | NORMAL |
| 3 | 18〜23 | HARD、段位（CLASS） |
| 4 | 24〜29 | EX-HARD、EX 段位（EXCLASS） |
| 5 | 30〜35 | HAZARD、EX-HARD 段位（EXHARDCLASS） |

組の中の 6 枚：

| 組の中の番号 | 意味 |
|---:|---|
| 0 | 点いている粒（ボーダー以上の所。以下「赤」） |
| 1 | 点いている粒（ボーダー未満の所。以下「緑」） |
| 2 | 消えている粒（赤） |
| 3 | 消えている粒（緑） |
| 4 | 光る粒（いちばん上の点いている粒。赤） |
| 5 | 光る粒（緑） |

「赤・緑」は、その粒の位置（下の 6.3）がボーダーより下なら「緑」、ボーダー以上なら「赤」です。
ボーダーが 0 のゲージ（HARD など）は、すべて「赤」になります。

### 6.2 スキンの画像から 36 枚への割り当て

LR2 CSV の `#SRC_GROOVEGAUGE`：

- マス 4 つで 1 組です：0 点いた赤、1 点いた緑、2 消えた赤、3 消えた緑。
- この 4 枚を、6 つの組すべてに使います。光る粒（4・5）には、点いた粒（0・1）と同じ画像を使います。
- アニメーションの種類（14 列目）が 3（点滅）で、マスの数が 6 で割り切れる時だけ、マス 6 つで 1 組：
  0 点いた赤、1 点いた緑、2 消えた赤、3 消えた緑、4 光る赤、5 光る緑。これを 6 つの組すべてに使います。
- 組が 2 つ以上あれば、アニメーションのコマです（cycle・timer）。

LR2 CSV の `#SRC_GROOVEGAUGE_EX`：

- マス 8 つで 1 組です：0〜3 はふつうのゲージ用（並びは上と同じ）、4〜7 は EX 用（EX の点いた赤・点いた緑・消えた赤・消えた緑）。
- ふつうのゲージ用は組 0〜3（ASSIST EASY, EASY, NORMAL, HARD）に、EX 用は組 4・5（EX-HARD, HAZARD）に使います。
  光る粒には、それぞれの点いた粒と同じ画像を使います。
- 点滅（アニメーションの種類 3）で、マスの数が 12 で割り切れる時は、マス 12 で 1 組：
  0〜3 ふつう、4〜7 EX、8・9 ふつうの光る赤・緑、10・11 EX の光る赤・緑。

JSON の `gauge`（`nodes` に画像の名前を並べる）：

| `nodes` の数 | 割り当て |
|---:|---|
| 4 | 0 点いた赤、1 点いた緑、2 消えた赤、3 消えた緑。6 つの組すべてに使い、光る粒は点いた粒と同じ |
| 8 | 0〜3 を組 2・3（NORMAL, HARD）に、4〜7 を組 0・1・4・5（ASSIST EASY, EASY, EX-HARD, HAZARD）に使う。光る粒は点いた粒と同じ |
| 12 | 0〜3 を組 2・3 に、4〜7 を組 0・1・4・5 に、8・9 を組 2・3 の光る赤・緑に、10・11 を組 0・1・4・5 の光る赤・緑に使う |
| 36 | そのまま 0〜35 |

**LR2 の `_EX`（8 マス）と JSON の 8 つは、組の分け方が違います。**
LR2 の `_EX` は「ASSIST EASY〜HARD」と「EX-HARD・HAZARD」に分け、JSON の 8 つは「NORMAL・HARD」と「それ以外」に分けます。
どちらが LR2 本体・beatoraja 本家と同じかは確かめていません（未確認）。

JSON の `nodes` の各画像を `divx`・`divy` で分けると、分けた数がアニメーションのコマになります（すべての画像で同じ数にする前提）。

### 6.3 粒の数と、点く粒

- 粒の数（parts）：LR2 CSV は 13 列目、JSON は `parts`（既定 50）。
  LR2 CSV で 0 を書くと、粒 50（PMS の 9 鍵では 24）・アニメーションの種類 0・範囲 3（PMS では 0）・間隔 33 ms の既定値を使います。
- ゲージの最大値を max、今の値を v とすると、点いている粒の数 n は：
  v が 0 より大きければ「v × parts ÷ max の切り捨て」と 1 の大きい方、v が 0 以下なら 0。
  （値が少しでもあれば、最低 1 粒は点きます。）
- i 番目の粒（1 から parts まで）の位置は「i × max ÷ parts」です。これがボーダーより小さければ「緑」の画像です。
- ボーダーと max は、**毎フレーム、今のゲージの種類のもの**を使います。
  ゲージの自動切り替えで種類が変わると、その場で赤・緑の境目と画像の組が変わります。
- 粒は、ゲージの枠を parts 等分した位置に、左から 1, 2, … の順に置きます。

7 鍵の譜面を 9 鍵に変えて遊ぶ時（7to9）だけ、最初の 1 回、ボーダーが粒の境目にちょうど来るように粒の数を増やします
（各ゲージの種類について、parts 以上で「ボーダーが（max ÷ 粒の数）で割り切れる」最小の粒の数を探し、その最大を使う）。

Arena の NantokaMania のルールで遊ぶ時は、粒の数を 50 に固定します（Arena だけ）。

### 6.4 光り方（アニメーションの種類）

| 種類 | 名前 | 動き |
|---:|---|---|
| 0 | ランダム | 間隔（ms）ごとに、0〜範囲の数をランダムに選ぶ（a とする） |
| 1 | 増える | 間隔ごとに a を 1 つ減らす（0 の次は範囲に戻る） |
| 2 | 減る | 間隔ごとに a を 1 つ増やす（範囲の次は 0 に戻る） |
| 3 | 点滅 | 下の説明 |

種類 0〜2 の描き方：

- n 番目の粒（いちばん上の点いた粒）は、光る粒の画像。
- n - a より下の粒は、点いた粒の画像。
- それ以外（n - a 以上の粒と、n より上の粒）は、消えた粒の画像。
- つまり、いちばん上の粒の下にある a 粒が、ちらちらと消えて見えます。

種類 3（点滅）の描き方：

- 1〜n 番目の粒は点いた粒、それより上は消えた粒の画像。
- さらに n 番目の粒の上に、光る粒の画像を重ねます。重ねる画像の不透明度は、間隔（ms）を 1 周とする三角波で、0 → 1 → 0 と変わります。

LR2 CSV の列：14 列目が種類、15 列目が範囲、16 列目が間隔（ms）です。JSON は `type`・`range`（既定 3）・`cycle`（既定 33）です。

### 6.5 リザルトでの伸びる演出

- リザルト画面では、ゲージの値は「そのプレイの最後の値」です（コースリザルトは最後の曲の最後の値）。ゲージの種類はリザルトのゲージの種類です。
- starttime より前は、そのゲージの最小値です。
- starttime 〜 endtime の間は、「max × (経過時間 - starttime) ÷ (endtime - starttime)」と最小値の大きい方で、最後の値を超えない値です。
- endtime 以降は最後の値です。
- 既定は starttime 0、endtime 500 です。LR2 CSV は 17・18 列目、JSON は `starttime`・`endtime`。
- 経過時間は、リザルト画面に入ってからの時間です（部品のタイマーではなく画面の時間。未確認）。

### 6.6 LR2 CSV の `#DST_GROOVEGAUGE` の位置

- 11 列目（add_x）・12 列目（add_y）は、`#SRC_GROOVEGAUGE` の 1 粒の大きさです。
- add_x の絶対値が 1 以上なら、ゲージの幅は「add_x × 50」です（**粒の数にかかわらず 50 倍**）。0 なら DST の w を使います。
- add_y も同じで、絶対値が 1 以上なら高さは「add_y × 50」です。0 なら DST の h を使います。
- add_x が負なら、幅は負になり、左端は「x ＋ |add_x|」に動きます。粒は右から左へ並びます（2P 側用）。
  負の幅の画像が左右反転して見えるかは確かめていません（未確認）。
- add_y が 1 以上の時、ゲージは y から下へ「add_y × 50」の高さを取ります。

### 6.7 Lua の `P1_grooveflash` など

`P1_grooveflash` という名前は、oraja のコードにはありません。スキン側の Lua の名前と考えられます。
元のプレイヤーから見ると、これはふつうの画像の部品で、ゲージの部品とは関係なく、スキンが決めた固定の位置に描かれます。
そのため、ゲージの描き方（粒の大きさや位置）が元のプレイヤーと違うと、光りの位置がずれて見えます。

### 7.1 譜面傾向のレーダー（A-1）

JSON の部品 `radargraph`：

| 項目 | 既定 | 意味 |
|---|---|---|
| `id` | | 部品の名前 |
| `color` | `ff0000` | 塗りの色（16 進数）。読めなければ赤。不透明度は**常に 50%**（色の透明度の指定は使わない） |

描き方：

- 今の曲（選曲画面ならカーソルの曲）の譜面傾向を、6 本の軸の六角形で塗ります。曲が変わった時に描き直します。
- 枠（destination の幅と高さ）の真ん中が中心です。半径は「幅と高さの小さい方の半分 - 2」画素です。
- 軸は上から時計回りに、60 度ずつ：上＝NOTES、右上＝PEAK、右下＝SCRATCH、下＝SOFLAN、左下＝CHARGE、左上＝CHORD。
- 各軸の長さは「値 ÷ 200」（0〜1 に収める）× 半径です。
- 中心と隣り合う 2 つの頂点の三角形 6 つで塗ります。輪郭や目盛りは描きません。
- 曲に譜面傾向の値が無い時は、何も描きません。

数値 1330〜1335（NUMBER）：

| 番号 | 軸 | 値の求め方（0〜200 に収めた整数） |

| 1331 | PEAK | 1 秒ごとのノーツ数の最大を 25 で割って 100 倍 |
| 1332 | SCRATCH | スクラッチのノーツの割合を 0.15 で割って 100 倍 |
| 1333 | SOFLAN | 最大 BPM ÷ 最小 BPM - 1 を 100 倍（BPM が変わらなければ 0） |

### 7.2 Skin Scene v1（A-2）

形式の仕様は、oraja のリポジトリの `docs/SKIN_SCENE_FORMAT.md`（公開の文書）にまとまっています。BMZ の担当もそのまま読めるよう、要点だけ書きます。

- JSON の配列の名前は `scenes` です（`scene` は画面の表示時間の数値で、名前がぶつかるため）。Lua も同じ。
- 1 つの scene は、ふつうの部品 1 つとして destination の順に入ります。位置・色・回転・オフセット・表示の条件は destination の決まりのままです。
- scene の名前がほかの部品の名前と重なるか、読み込みに失敗したら、その destination だけを使わず、同じ名前の画像などで代わりにしません。
- `cycle`（ms）が 0 なら文書の長さを使います。`timer` が 0 か省略なら画面に入った時から進みます。時刻はフレームごとの絶対時間で、スキンの描画の間引き（prepare FPS）の影響を受けません。
- scene の文書は、テクスチャ・メッシュ・clip・instance（入れ子・変形・色・カメラ・マスク）を持ちます。細部は上の文書を読んでください。

BMZ は描画の作りがまったく違うため、調査では「大」としました。この文書では動きの細部を足しません。

### 7.3 文字の縦グラデーション（A-3）

Arena oraja の項目（JSON・Lua の `text`）：

| 項目 | 意味 |
|---|---|
| `gradientTopColor` | 上の色。`RRGGBBAA`（`RRGGBB` も読める） |
| `gradientBottomColor` | 下の色 |

- **2 つとも書いた時だけ**グラデーションにします。片方だけなら、いつもの 1 色で描きます。
- 色が読めない時は白として扱います。
- 色は destination の枠の**上の辺から下の辺まで**で、上の色から下の色へ直線で変わります。
  文字の各字の上端・下端の位置で色を決め、その間はなめらかにつながります。枠の外にはみ出た所は、端の色です。
- destination の色と不透明度を、上の色・下の色の両方に掛けます。色やフェードのアニメーションはそのまま効きます。
- 影（`shadowOffsetX/Y`）は、グラデーションを使わず、1 色で描きます（`shadowColor` があればその色、無ければ文字の色の半分の明るさ）。
- 効くのは TrueType / OpenType のフォント（`.ttf` など）の文字だけです。ビットマップのフォント（`.fnt`）の文字には効きません。
- 縁取り（`outlineColor`）にもグラデーションの色が掛かるかは確かめていません（未確認。縁取りはフォントの画像に焼き込まれるため、掛かる見込み）。

#1586 の決定は「BMZ の名前（`colorTop` 系）と Arena の名前（`gradientTopColor` 系）の両方を受け付ける」です。
BMZ の `colorTop` 系との違い（BMZ は片方だけでも有効、向きの角度あり、横の範囲は字の範囲、など）は BMZ の `docs/skin.md`「Text Gradient」にあります。
両方が書かれたスキンでどちらを優先するかは、まだ決まっていません。
