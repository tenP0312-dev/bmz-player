# 仕様書：ワンバス入力

最終更新：2026-11-12（Issue #1580 の「3. 仕様書」、調査の P1）

BMZ（`hyrorre/bmz-player`）へ移す機能の仕様です。実装はまだしていません。
実装の前に、BMZ の最新の `AGENTS.md` と対象の文書を読み直してください。本家の内容が優先します。

読んだ版：BMZ `54c9503`（0.5.1）、Arena oraja `9474d78`（0.4.14.129）。
どちらもビルド・起動していません。コードと文書を読んだ結果です。

## 1. 目的と、利用者から見た動き

- LR2 の「ワンバス」と同じ操作です。配置オプションが通常の RANDOM のとき、START と鍵盤を 1 つ
  押したまま曲を始めると、**元の譜面の 1 鍵のノーツが、押していた鍵盤のレーンに来ます**。
  残りのレーンは RANDOM のままです。
- バスドラムなどが 1 鍵に置かれた譜面で、好きな位置に固定して遊ぶための操作です。
- できあがる配置は、通常の RANDOM で出る配置の 1 つです。seed も通常の RANDOM の seed です。
  スコアやリプレイに、ワンバス専用の情報は残しません。

### 設定

| 項目 | 内容 |
| --- | --- |
| 名前（案） | 「START + 1 鍵で 1 鍵の位置を決める（ワンバス）」 |
| 置き場所 | プロファイルのプレイ設定。「BMZ メニュー → プロファイル」と選曲画面の設定の両方 |
| 既定値 | **OFF**（案）。Arena oraja の既定は ON。BMZ の今の動きを変えないため OFF をすすめる（8 章） |

### 操作（BMZ での案）

1. 選曲画面で、配置オプションを RANDOM にして曲を決定する。
2. 決定画面が出ている間に、E1（START）と鍵盤を 1 つ押す。
3. 決定画面が終わってプレイ画面へ移る瞬間まで、押したままにする。
4. プレイ画面（ロード中）が出たら離してよい。

## 2. 細かい動きの決まり

### Arena oraja の動き（読み取った結果）

- 入力を読むのは 1 回だけです。決定画面からプレイ画面へ移り、譜面の配置を決める瞬間です。
  決定画面を出さない設定のときは、曲を決定した時点で押している必要があります。
- 条件は「START を押している」かつ「その側の鍵盤（スクラッチを除く）を**ちょうど 1 つ**押している」です。
  0 個、2 個以上なら、ワンバスは働きません。スクラッチは数えません。
- 対象のキーモードは 5 鍵・7 鍵・10 鍵・14 鍵・9 鍵（PMS）です。24 鍵などでは働きません。
- DP は 1P 側と 2P 側を別々に見ます。その側の配置が RANDOM で、その側の鍵盤をちょうど 1 つ
  押していれば、その側だけに働きます。「元の 1 鍵」は、その側のいちばん左の鍵盤です。
- 働かないとき：オートプレイ、リプレイ再生、プラクティス、同じ配置でのやり直し、FLIP、
  RANDOM 以外の配置（MIRROR、R-RANDOM、S-RANDOM など）、7 鍵 → 9 鍵の変換中、
  Arena で対戦が決まったあとと対戦中。Arena につないでいるだけ・待っているだけなら働きます。
- seed の決め方：
  1. 今の seed の配置が、もう条件（元の 1 鍵が押した鍵盤に来る）を満たしていれば、seed を変えない。
  2. 配置を借りていない通常のプレイでは、条件を満たす通常の RANDOM の seed（24 bit）を新しく選ぶ。
  3. 相手やリプレイから RANDOM の配置を借りているときは、借りた配置を基準にして、
     「元の 1 鍵が今いるレーン」と「押した鍵盤のレーン」の 2 つだけを入れ替える。
     できあがった配置と同じ配置になる通常の seed を探して、それを使う。
  4. seed のない借用（オプションだけを借りた場合）は、2 と同じく新しく選ぶ。
  5. どうしても seed が見つからないときは、ワンバスをやめて通常の RANDOM で始める。
- 結果として、seed だけで最終の配置を再現できます。リプレイと、IR 経由の配置の借用は、
  ワンバスを知らなくても同じ配置になります。
- コース・段位での動きは、文書に書かれていません。コードでは、はっきり止めている箇所が
  見つかりませんでした（実行での確認は**未確認**）。

### 配置と seed の決まり

- BMZ の新しいプレイの seed は、beatoraja と同じ 24 bit の方式です（`0..=16777215`）。
  DP は側ごとに別の seed を持ちます。ワンバスで選ぶ seed も、必ずこの範囲に入れます。
- 「元の 1 鍵」は、キー数の変換をする前の、その側のいちばん左の鍵盤です。
- 条件を満たす seed を新しく選ぶときは、通常の seed を引き直して、条件を満たすものを採ります
  （レーンが n 本なら、平均で n 回ほどで見つかります）。回数に上限を置き、超えたら範囲を
  順に調べます。
- 借りた配置を入れ替えたあとの seed は、「その配置になる seed」を 24 bit の範囲から探します。
  Arena oraja のテストでは、5・7・9 レーンのすべての並びに、24 bit の seed があることを確かめて
  います。BMZ の Random Trainer には、7 レーンの並びから seed を探す処理がすでにあります。
- 9 レーン（PMS）は並びが 362,880 通りあります。探す時間を実装のときに測ります。
  遅ければ、1 度作った対応表を使い回します。

## 3. BMZ での実装方針

### 入れる場所

| 部分 | 場所（`crates/bmz-player/src/`） |
| --- | --- |
| 配置と seed の計算（入力から seed を返す、状態を持たない関数） | 新しいモジュール。`random_trainer.rs`、`random_option_seed.rs` の隣 |
| 入力を読んで、seed を差し替える | 決定画面からプレイ画面へ移る処理（`app/result_flow/transition.rs`、`app/play_flow/launch/`） |
| 設定の値 | `config/profile_config/`、`config/settings_registry/` |
| 設定の画面 | `ui/profile_panel/`、選曲画面の設定 |
| 翻訳 | `i18n/locales/`（6 言語） |

`bmz-gameplay`、`bmz-chart`、スキン、描画には手を入れません。配置の適用は、今ある RANDOM の
処理をそのまま使います。ワンバスが変えるのは「どの seed を渡すか」だけです。

### いちばん大きい設計上の点：読み込みのやり直し

- BMZ は、曲を決定した時点で seed を決め、決定画面を出している間に裏で譜面と音の読み込みを
  始めます。配置もこの読み込みの中で適用します。
- 選曲画面では、E1 を押している間はオプションのパネルが出て、E1 + 鍵盤はオプションの変更に
  なります。そのため「決定の瞬間に E1 + 鍵盤を押している」という読み方はできません。
- そこで、決定画面の終わりに入力を読みます。ワンバスが働くと seed が変わるので、
  **その時点で読み込みをやり直します**（今ある「読み込みの取り消し」と「読み込みの開始」を使う）。
- やり直しの間、ロード中の画面が長くなります。どのくらい延びるかは**未確認**です（実装のときに測る）。
- 「別の配置でのクイックリトライ」は、譜面を読み直す作りでした。読み込んだ音を使い回して
  やり直しを短くできるかは**未確認**です。

### 実装で必ず確かめる点（未確認）

- 決定画面から出るとき、BMZ は操作の「押しっぱなし」の記録を消します。ワンバスの判定には、
  その瞬間の実際の押下の状態が要ります。入力の層（`input/`）から読めるかを確かめます。
- プレイ画面では、E1 + 鍵盤は HS の変更です。決定画面から押しっぱなしで入ったときに、
  HS が動かないこと（新しく押した扱いにならないこと）を確かめます。動くなら、離すまで
  その入力を HS の操作に使わないようにします。
- 決定画面では、鍵盤を押すと先へ進みます（決定キーとして働く）。これは今の動きのままにします。
- 決定画面を出さない起動オプションがあります。その場合の読む瞬間（曲を決定した時点）を決めます。
- E4 は、プレイ画面では E1 と同じ扱いです。決定画面の終わりで E4 も START として数えるかを、
  プレイ画面の決まりに合わせて決めます。

## 4. 既存の動作を変えないことの確認点

- 設定が OFF なら、入力を読む処理に入らない。今の BMZ と 1 つも変わらない。
- スコア：配置は通常の RANDOM、seed は通常の 24 bit。`score.db`、スコアを分ける単位、
  アシストの扱いは変えない。ワンバスのプレイは、通常の RANDOM のプレイとして保存する。
- IR：送る内容は、配置 `random` と通常の seed だけ。新しい項目を足さない。どの IR へも今と同じ形で送る。
- リプレイ：形式を変えない。seed だけで配置を再現できる。
- G-BATTLE、AUTOPLAY BATTLE：最初の版では働かない。相手の配置の借用も、SP の G-BATTLE で
  右側から自分の配置を変える操作も、今のまま。
- Random Trainer：有効なら Trainer を優先する。Trainer の seed の決め方は変えない。
- コース・段位：働かない。段位の制約に触らない。
- 譜面の `#RANDOM` / `#SWITCH` の選択：変えない。ワンバスが差し替えるのは配置の seed だけ。
- ゲージ、判定、HS、レーンカバー：触らない。

確認が要る点：ワンバスは、利用者が配置の一部を選ぶ操作です。BMZ がこれを「通常のスコア」として
扱ってよいか（LR2 では通常のプレイ）を、本家の PR の説明にはっきり書きます。

## 5. テストの観点と、手での確認

### 単体テスト

計算の部分：

- 5K / 7K / 9K と、10K / 14K の各側について、すべての鍵盤を押した場合に、元の 1 鍵が
  そのレーンに来る。結果がその側の並べ替えになっている（重複・欠けがない）。スクラッチは動かない。
- 選んだ seed が 24 bit の範囲に入り、その seed を通常の RANDOM に渡すと同じ配置になる。
- 今の seed がもう条件を満たすとき、seed が変わらない。
- 借りた配置：入れ替えたあと、借りた配置との違いが 2 レーン以下。seed `0` も正しい seed として扱う。
- seed のない借用：新しい seed を選ぶ。
- 5・7・9 レーンのすべての並びに、24 bit の seed がある。
- 対象外のキーモードと、範囲の外の seed では「働かない」を返す。

入力の判定：

- START なし → 働かない。START + 鍵盤 1 つ → そのレーン。START + 鍵盤 2 つ → 働かない。
- START + 鍵盤 1 つ + スクラッチ → 鍵盤のレーン（スクラッチは数えない）。
- DP：1P 側 1 つ、2P 側 1 つ → 両側。1P 側 1 つ、2P 側 2 つ → 1P 側だけ。

画面の流れ（今ある app のテストに足す）：

- 設定 OFF：押していても seed が変わらない。読み込みをやり直さない。
- 設定 ON で条件を満たす：seed が差し替わり、読み込みが 1 回だけやり直される。古い読み込みの
  結果は使われない。
- 2 章の表の「働かない」場面（MIRROR、FLIP、PRACTICE、AUTOPLAY、G-BATTLE、コース、
  Random Trainer、キー数の変換、CLI の seed）で、seed が変わらない。
- 押しっぱなしでプレイ画面に入っても、HS が変わらない。
- クイックリトライ（同じ配置）で同じ配置になる。

### 手での確認（オペレーター向け）

1 鍵にだけノーツが続く、分かりやすい譜面（7 鍵）を 1 つ用意します。

1. 設定を OFF のまま、RANDOM で、決定画面の間 E1 + 4 鍵を押して始める。配置が通常の RANDOM で、
   毎回変わることを見る。
2. 設定を ON にする。RANDOM で、決定画面の間 E1 + 4 鍵を押したまま始める。
   元の 1 鍵のノーツが 4 鍵のレーンに来ることを見る。3 回くり返し、毎回 4 鍵に来て、
   ほかのレーンは変わることを見る。
3. ほかの鍵盤（1 鍵、7 鍵）でも同じことを見る。
4. E1 + 鍵盤 2 つで始める。通常の RANDOM になることを見る。
5. 配置を MIRROR にして E1 + 4 鍵で始める。MIRROR のままであることを見る。
6. ワンバスで始めたとき、HS が勝手に変わっていないことを見る。ロード中の時間が、
   気になるほど延びていないことを見る。
7. ワンバスのプレイを最後まで遊び、リザルトへ進む。リプレイを再生し、同じ配置になることを見る。
8. FAILED の演出中に E2（同じ配置でやり直し）を押し、同じ配置になることを見る。
9. 14 鍵の譜面で、1P 側と 2P 側の鍵盤を 1 つずつ押して始め、両側とも働くことを見る。
10. 9 鍵（PMS）の譜面でも働くことと、始まるまでの時間を見る。
11. IR へ送ったスコアが、通常の RANDOM のスコアとして出ていることを見る。

## 6. 調査で「未確認」だった項目の確認結果

| 項目 | 結果 |
| --- | --- |
| P1：配置を通常の 24 bit の seed に直して保存できるか | **できる**。BMZ の新しいプレイは beatoraja と同じ 24 bit の方式で、Random Trainer に並びから seed を探す処理（7 レーン）がすでにある |
| P1：G-BATTLE の配置の借用との関係 | Arena oraja は、借りた配置の 2 レーンだけを入れ替える。BMZ の最初の版では、G-BATTLE ではワンバスを働かせない（今の G-BATTLE を変えないため）。ライバルの配置の借用（通常のプレイ）には、同じ「2 レーンの入れ替え」を使う |
| 新しく分かった点 | BMZ は決定の時点で seed を決めて読み込みを始めるので、ワンバスが働くと読み込みのやり直しが要る（3 章） |

## 8. 決めてほしいこと

1. **既定値**。OFF（BMZ の今の動きを変えない）でよいか。Arena oraja は ON。
2. **最初の版の範囲**。コース・段位、G-BATTLE、Random Trainer が有効なときは「働かない」でよいか。
3. **読み込みのやり直し**。ロード中の時間が延びる作りでよいか。延びが大きいと分かったら、
   別の読み方（たとえば選曲画面に専用の操作を足す）を本家と相談するか。
4. **PR の分け方**。上の 2 つに分ける進め方でよいか。
