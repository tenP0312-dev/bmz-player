# 仕様書：開始前（READY）に最初のノーツを表示する

最終更新：2026-11-12（Issue #1580 の「3. 仕様書」、調査の P2）

BMZ（`hyrorre/bmz-player`）へ移す機能の仕様です。実装はまだしていません。
実装の前に、BMZ の最新の `AGENTS.md` と対象の文書を読み直してください。本家の内容が優先します。

読んだ版：BMZ `54c9503`（0.5.1）、Arena oraja `9474d78`（0.4.14.129）。
どちらもビルド・起動していません。コードと文書を読んだ結果です。

## 1. 目的と、利用者から見た動き

- 曲が始まる前（譜面のロード中と READY の間）に、**その譜面で最初に叩くノーツ**を、
  レーンのいちばん上に並べて見せます。
- RANDOM の配置を、曲が始まる前に確かめられます。ワンバス入力（`SPEC_ONE_BASS_INPUT.md`）と
  一緒に使うと、狙った位置に来たかがすぐ分かります。
- 表示には、使っているスキンのノーツの画像をそのまま使います。新しい画像やスキンの部品は足しません。
- 曲が始まった瞬間に消え、そのあとは今までどおりの表示です。

### 設定

| 項目 | 内容 |
| --- | --- |
| 名前（案） | 「ロード中・READY 中に最初のノーツを表示する」 |
| 置き場所 | プロファイルの表示の設定。「BMZ メニュー → プロファイル」の「表示」と、選曲画面の設定 |
| 既定値 | **OFF**（案）。Arena oraja の既定は ON。この表示の間は通常のノーツを描かないので、今の見え方を変えないため OFF をすすめる（8 章） |

操作は足しません。

## 2. 細かい動きの決まり

### Arena oraja の動き（読み取った結果）

どのノーツを出すか：

- 配置（RANDOM など）を適用したあとの譜面から決めます。
- 譜面の先頭から見て、**最初に「叩くノーツ」がある時刻**を 1 つ決めます。
  地雷ノーツと、ロングノートの終わりは「叩くノーツ」に数えません。ロングノートの始まりは数えます。
- その時刻にあるノーツを、すべて出します（同時押しなら複数）。スクラッチのレーンも含みます。
  1 つのレーンには 1 つだけです。
- DP は、両側を合わせた 1 つの時刻で決めます。片側の最初のノーツが遅ければ、その側には何も出ません。
- 叩くノーツが 1 つもない譜面では、この表示をしません。

いつ出すか：

- 設定が ON で、プレイ画面の状態が「ロード中」か「READY」の間です。
  ロード中は、配置を決めた譜面とスキンのノーツが描けるようになった時点から出ます。
- 曲が始まった時点で消えます。プラクティスの設定画面では出ません。
- オートプレイやリプレイ再生で止めている箇所は、コードには見つかりませんでした（実行での確認は**未確認**）。

どこに、どう出すか：

- 各レーンのノーツの画像を、そのレーンの幅と、そのスキンのノーツの厚みで描きます。
  ロングノートの始まりも、通常のノーツの画像で描きます。
- 縦の位置は、SUDDEN+ のカバーを出していなければ**レーンのいちばん上**、出していれば
  **カバーのすぐ下**です。LIFT を使っていれば、レーンの下の端が上がった分を計算に入れます。
  カバーと LIFT の量は 0〜1 の範囲に収めます。
- 開始前に HS やカバーを動かすと、表示の位置も一緒に動きます。
- 明るさは、1 秒の周期でゆっくり変わります（不透明度 65% → 100% → 65%）。
- この表示をしている間は、**通常の譜面の描画（流れてくるノーツなど）をしません**。
- どれか 1 つのレーンでもノーツの画像がない、または幅や厚みが 0 以下になるスキンでは、
  この表示をやめて、通常の描画をします。

そのほか：

- 表示だけの機能です。判定、スコア、リプレイ、IR には関係しません。
- HS の計算（緑数字など）は、この表示の間も今までどおり行います。

### BMZ での決まり

| 場面 | 動き |
| --- | --- |
| 設定が OFF | 何もしない。今の BMZ と同じ |
| 出す期間 | READY の間（必須）。ロード中は、配置を適用した譜面が用意できた時点から（3 章で 2 段階に分ける） |
| 消える時点 | プレイの状態が Playing になった時点。中断して選曲へ戻るときも消える |
| 出すノーツ | 上の「どのノーツを出すか」と同じ。不可視ノーツ（INVISIBLE）は数えない |
| 位置 | SUDDEN+ を表示していなければレーンのいちばん上。表示していればカバーのすぐ下。LIFT を計算に入れる |
| HIDDEN+ | 位置の計算には使わない（Arena oraja と同じ）。HIDDEN+ が上まで覆って見えない場合も、そのまま |
| 明るさ | 1 秒の周期で 65%〜100% |
| 通常の描画 | この表示をしている間は、流れてくるノーツ・ロングノート・地雷を描かない |
| 出せないとき | 叩くノーツがない譜面、ノーツを描けないスキン → この表示をやめ、通常の描画をする |
| SESSION MODE | NORMAL、G-BATTLE、AUTOPLAY、AUTOPLAY BATTLE、リプレイ再生で出す。PRACTICE では出さない |
| コース・段位 | 各曲の開始前に出す |
| クイックリトライ | やり直しの開始前にも出す |
| Viewer、動画の書き出し | 出さない（出力される映像を変えないため） |
| DP、BATTLE | 両側を合わせた 1 つの時刻で決める |
| 9K（PMS） | 同じ決まり。見逃しノーツの落下の表示とは関係しない |
| ワンバス入力と一緒のとき | ワンバスで決まった最終の配置を出す。読み込みをやり直している間は、古い配置を出さない |

## 3. BMZ での実装方針

### 入れる場所

BMZ の描画は、`bmz-player` が作る「1 フレーム分の写し」（レーンごとの見えるノーツの一覧。
ノーツごとに縦の位置と不透明度を持つ）を、`bmz-render` がスキンのノーツの画像で描く作りです。

- この機能は、**写しを作る側（`bmz-player` の `screens/play_snapshot/`）だけ**で実装します。
  READY の間、見えるノーツ・ロングノート・地雷の一覧を空にして、代わりに「最初のノーツ」を
  決まった位置と不透明度で入れます。
- `bmz-render`、`bmz-skin`、`bmz-skin-document` には手を入れません。スキンの部品も参照番号も足しません。
  既定のスキンでも、外部のスキンでも、同じ写しを描くので、同じように出ます。
- 「最初のノーツ」の一覧は、譜面を用意したときに 1 度だけ作ります（状態を持たない関数）。
  描画用のキャッシュ（`screens/play_snapshot/cache.rs`）に置きます。
- 設定の値は `config/profile_config/` と `config/settings_registry/`、画面は `ui/profile_panel/`、
  翻訳は `i18n/locales/` です。

### 2 段階に分ける

1. **READY の間**。プレイの session ができたあとなので、写しを作る今の処理に足すだけで済みます。
2. **ロード中**。session ができる前です。BMZ は、ロード中の画面に用意できた譜面の情報
   （曲名、ノーツ数など）を写しています。ここで見えるノーツを入れて描けるか、そのときの
   カバーと LIFT の値がそろっているかは**未確認**です。確かめてから足します。

### 実装で必ず確かめる点（未確認）

- 写しの縦の位置は「0 が判定ライン、1 が画面の上の端」です。SUDDEN+ を出しているときに
  「カバーのすぐ下」になる値を、今の HS の計算（見えているレーンの割合）から求め、テストで固定します。
- ノーツの厚みの分だけ、上の端からはみ出さない位置にします。スキンごとに厚みが違うので、
  既定のスキンと同梱スキンで確かめます。
- BMZ は今、READY の間も通常のノーツを描いています。この表示の間に通常のノーツを消すことで、
  READY の演出（スキンの READY の画像など）に影響がないことを確かめます。
- READY の間に動く BGM の先行予約と、開始前の入力の処理は、gameplay 側の仕事です。触りません。
- 小節線は、Arena oraja では通常の描画と一緒に出なくなる作りに見えます。BMZ で小節線も消すかは、
  実際の見え方を見て決めます。

### BMZ の AGENTS.md の決まりとの対応

| 決まり | 対応 |
| --- | --- |
| crate の責任 | `bmz-player` だけを変える。描画の評価（`bmz-render`）とスキンの読み込みには入れない |
| スキンの互換 | 他人のスキンを書き換えない。スキンの仕様（`docs/skin.md`）を変えない |
| スレッド | 写しを作る処理の中だけ。gameplay 専用スレッドの session の状態は変えない |
| 文書の更新 | `docs/settings.md`（設定の項目）。プレイ画面の見え方として `docs/controls.md` か `docs/hs.md` に 1 節足すかは本家に合わせる |
| 6 言語の翻訳 | 設定の名前と説明を 6 言語のカタログすべてに足す |
| テスト | 5 章 |
| 確認 | `cargo fmt --check`、`bmz-player` の `check` / `clippy -D warnings` / `test`。見え方は対象の OS で実機の確認 |
| コミット | Conventional Commits。scope は `bmz-player` |

## 4. 既存の動作を変えないことの確認点

- 設定が OFF なら、写しを作る処理は今と同じ結果になる（テストで固定する）。
- 判定・スコア・ゲージ：写しは描画のための写しで、判定には使われない。session を書き換えない。
- リプレイ：記録にも再生にも関係しない。
- IR：送る内容に関係しない。
- G-BATTLE、AUTOPLAY BATTLE：相手側の表示（相手のレーン）は変えない。自分のレーンだけに出す。
- スキン：部品も番号も足さない。スキンが読む値（ノーツ数、BPM、緑数字など）は変えない。
- Viewer と動画の書き出し：出さない。書き出される映像が今と同じであることを確かめる。
- 曲が始まったあとの描画：1 フレーム目から今と同じ。表示の切り替えで、ノーツが 1 フレーム
  消えたり、二重に出たりしないことを確かめる。

## 5. テストの観点と、手での確認

### 単体テスト

「最初のノーツ」の一覧：

- 先頭の時刻にあるノーツだけが入る。2 番目以降の時刻のノーツは入らない。
- 同時押しは、すべてのレーンが入る。スクラッチも入る。
- 先頭が地雷だけ、またはロングノートの終わりだけの時刻は飛ばし、次の「叩くノーツ」の時刻を使う。
- ロングノートの始まりは入る。不可視ノーツは入らない。
- DP：両側を合わせた 1 つの時刻。遅い側には入らない。
- 叩くノーツがない譜面 →「出せない」。
- RANDOM を適用した譜面では、適用後のレーンに入る。

位置と明るさ：

- カバーなし → いちばん上。SUDDEN+ あり → カバーのすぐ下。SUDDEN+ と LIFT の両方 → 計算どおりの位置。
- カバーと LIFT の量が範囲の外でも、0〜1 に収めた位置になる。
- 0 ミリ秒で 65%、500 ミリ秒で 100%、1000 ミリ秒で 65% に戻る。

写し：

- 設定 OFF：READY の写しが今と同じ。
- 設定 ON、READY：見えるノーツは「最初のノーツ」だけ。ロングノートと地雷の一覧は空。
- 設定 ON、Playing：今と同じ。
- 設定 ON、出せない譜面：READY でも今と同じ。
- PRACTICE、Viewer、動画の書き出しでは、設定 ON でも今と同じ。

### 手での確認（オペレーター向け）

1. 設定を OFF のまま 1 曲始める。READY の見え方が今までと同じであることを見る。
2. 設定を ON にして、同じ曲を RANDOM で始める。READY の間、レーンのいちばん上に最初のノーツが
   出て、ゆっくり明るさが変わることを見る。曲が始まると消え、実際に最初に来るノーツの
   レーンと合っていることを見る。
3. SUDDEN+ を出して始める。ノーツがカバーのすぐ下に出ることを見る。READY の間にカバーを
   動かし、ノーツが一緒に動くことを見る。
4. LIFT を使って同じことを見る。
5. 最初が同時押しの譜面、最初がスクラッチの譜面、最初がロングノートの譜面で、それぞれ正しく出ることを見る。
6. 14 鍵と 9 鍵（PMS）の譜面で見る。
7. 同梱の 3 つのスキンと既定のスキン、ふだん使っている外部のスキンで見る。ノーツの大きさや
   位置がおかしいスキンがあれば、スキン名と画面の写真を残す。
8. オートプレイとリプレイ再生で出ること、プラクティスの設定画面で出ないことを見る。
9. ワンバス入力を ON にして、決めた位置に最初のノーツが出ることを見る（ワンバスの実装のあと）。
10. 動画の書き出しを 1 つ行い、映像にこの表示が入っていないことを見る。

## 6. 調査で「未確認」だった項目の確認結果

| 項目 | 結果 |
| --- | --- |
| P2：ロード中の画面にスキンのノーツを描けるか | READY の間は、今ある「見えるノーツの一覧」を差し替えるだけで描ける（スキンにも描画にも手を入れない）。ロード中（session ができる前）に描けるかは**未確認**のまま。2 段階目で確かめる |
| P2：スキンごとの見え方 | コードでは、既定のスキンも外部のスキンも同じ一覧を描く。実際の見え方は起動していないので**未確認**。5 章の手での確認で見る |
| 新しく分かった点 | Arena oraja は、この表示の間、通常の譜面の描画をしない。BMZ は今 READY の間もノーツを描いているので、ON にすると READY の見え方が変わる。既定を OFF にすすめる理由 |

## 7. 見積もりと PR の分け方

見積もり：READY の間だけなら**小**、ロード中も含めると**中**。

| PR | 中身 | 大きさ |
| --- | --- | --- |
| 1 | 「最初のノーツ」の一覧、READY の間の表示、設定、6 言語の翻訳、`docs/settings.md`、テスト | 小 |
| 2 | ロード中の表示（確かめた結果、できる場合だけ） | 小〜中 |

ワンバス入力とは別の PR にします。順番は、この機能（PR 1）を先にすると、ワンバスの手での確認が楽になります。

## 8. 決めてほしいこと

1. **既定値**。OFF でよいか。Arena oraja は ON。
2. **ロード中の表示**。まず READY の間だけを出し、ロード中は 2 段階目にする進め方でよいか。
3. **順番**。ワンバス入力より先にこの機能を出すか（調査のおすすめ順は、ワンバス → この機能）。
