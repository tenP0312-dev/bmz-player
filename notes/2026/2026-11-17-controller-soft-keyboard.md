# コントローラーで操作する画面キーボード

2026-11-17。[コントローラーだけで全操作するための洗い出し](2026-11-17-controller-only-inventory.md)の段階 1「画面キーボード」。
文字入力の欄から共通で使う部品だけを作り、選曲の検索・設定フォルダ・コース名へのつなぎ込みは段階 2 で行う。
操作の一覧は [controls.md の「画面キーボード」](../../docs/controls.md#画面キーボード文字入力の欄) を参照。

## 構成

`crates/bmz-player/src/ui/soft_keyboard.rs` と `ui/soft_keyboard/` に置いた。選曲・リザルトの画面のコードには依存しない。

| ファイル | 内容 |
|---|---|
| `layout.rs` | 文字種（`SoftKeyboardMode`）、文字盤、直前の文字の変換の輪 |
| `state.rs` | 状態機械 `SoftKeyboard`。欄の仕様 `SoftKeyboardFieldSpec`、操作 `SoftKeyboardAction`、結果 `SoftKeyboardOutcome` |
| `pad.rs` | 論理ボタン（KEY1〜7・皿・E1〜E4）から操作への対応 `SoftKeyboardPadMapper` |
| `draw.rs` | egui の描画 `draw_soft_keyboard`。マウス操作は `SoftKeyboardAction` の列で返す |
| `tests.rs` | 単体テスト |

使う側の流れは次のとおり。

1. `SoftKeyboard::open(spec)` で開く。
2. パッドの押下・解放を `SoftKeyboardPadMapper::press` / `release` で操作へ変換し、`apply` へ渡す。
3. 毎フレーム `draw_soft_keyboard` で描き、返ったマウス操作も `apply` へ渡す。
4. `take_outcome()` が `Submitted(String)` か `Cancelled` を返したら閉じる。

## 判断

- **入力は抽象的な操作で受ける。** 状態機械は `SoftKeyboardAction` だけを知り、物理ボタンとの対応は `pad.rs` に分けた。
  キーコンフィグで解決した後の論理ボタンを受けるので、キーボード・汎用パッド・専コンのどれでも同じ。
  DP の 2P 側は、呼び出し側で KEY1〜7 / 皿へ読み替える。
- **割り当ては、右手の鍵盤と左手の皿だけで入力が終わるようにした。**
  文字盤の横（最大 11 列）が長いので、速く回せる皿を左右に、鍵盤を上下（KEY2 / KEY4）に当てた。
  入力・変換・削除・文字種・確定を KEY1 / 3 / 5 / 6 / 7 に置き、E ボタンは空白・取消など頻度の低い操作だけにした。
  E4 はシステムボタンとして予約されているので、取消（閉じる）だけに使う。
- **確定は KEY7、取消は E2 / E4。** 入力を変更した後の取消は 2 回押しにして、うっかり押した E2 で入力を失わないようにした。
  ほかの操作をはさむと確認待ちは解除する。変更していない場合（元に戻した場合を含む）は 1 回で閉じる。
- **E1 は「単独で押して離すと空白」「押しながらは修飾」。** 空白の頻度は低いが、検索では使う。
  E1 hold 中は皿でキャレットを動かし、KEY5 ですべて消し、KEY6 で前の文字種へ戻る。E1 を組み合わせた場合、離しても空白は入れない。
- **濁点・半濁点・小書きは「直前の文字の変換」1 つにまとめた。**
  か→が→か、は→ば→ぱ→は、つ→っ→づ→つ、う→ぅ→ゔ→う、や→ゃ→や のように輪で回す。英字は大文字と小文字を入れ替える。
  専用のキーを 3 つ用意するより鍵盤を使わず、ガラケー入力に近い感覚で覚えやすい。
  変換結果が欄で使えない文字（ASCII だけの欄でのかな、小文字だけの欄での大文字）になる場合は、使える形まで輪を進め、無ければ変換しない。
- **文字種は 6 つ。** ひらがな・カタカナ・abc・ABC・記号（ASCII）・全角記号。
  BMS の曲名には ☆ ★ ♪ † や全角の括弧が多いので、全角記号を記号（ASCII）と分けて追加した。
  abc / ABC は大文字ロックの代わりに別ページにした。どちらにも数字と `- _ . @ / :` を置き、URL とメールアドレスを 1 ページで入力できる。
- **文字盤はすべて 11 列。** 文字種を切り替えても列を保てる。行数が少ない文字種へ移ると下端へ収め、空きマスなら同じ行の文字へ寄せる。
  50 音表の空きマス（やゆよ・わをの段）にはカーソルが止まらない。
- **欄の制限は `SoftKeyboardFieldSpec` で指定する。** 使える文字種（`ascii()` は abc / ABC / 記号）、最大の文字数（文字単位）、
  初期値（最大を超える分は切り捨て）、最初の文字種、パスワード表示（`●`）、空白の可否。
  呼び出し側が渡した初期値に使えない文字が含まれていても消さない（確定前の検証は呼び出し側で行う）。
- **最大の文字数は Unicode scalar で数える。** 書記素クラスターではないが、文字盤の文字はすべて 1 scalar なので入力上の差は出ない。
- **描画は状態を変更しない。** egui のウィンドウを画面中央の前面に出し、マウスのクリックは操作の列で返す。
  プラクティスの設定パネルと同じく、アプリ側が毎フレーム呼ぶ前提。

## 段階 2 へ残すこと

- パッド入力の経路へのつなぎ込み。画面キーボードを開いている間は、その入力を選曲・設定フォルダへ渡さない。
- 皿・鍵盤の長押しでの連続移動（キーリピート）。部品は 1 回の押下を 1 操作として扱うので、リピートは呼び出し側で押下を繰り返す。
- キーボード（物理）での操作。BMZ メニューの欄は今の egui の入力欄を使い続ける想定。
- 確定時の検証（空の検索、URL の形式など）とエラー表示。

## 検証

- 単体テスト（`ui::soft_keyboard::tests`）：カーソルの移動と折り返し、空きマスの飛ばし、文字種の切替とカーソルの保持、
  濁点・半濁点・小書きの変換、最大の文字数、パスワード表示、ASCII だけの欄、空白の禁止、確定・取消、パッドの割り当て、
  パッドの操作だけで「ぱ A」を入力する流れ、表示ラベルの翻訳キー。
- 画面での見た目（文字盤の幅、かなのグリフ、配色）は、つなぎ込み前のため実機では確認していない。
