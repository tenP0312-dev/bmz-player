# BMZ メニューと選曲画面の設定フォルダの差分

2026-11-17。[コントローラーだけで全操作するための洗い出し](2026-11-17-controller-only-inventory.md)の段階 1「設定フォルダの拡充（文字入力なし）」の記録。
対象は `claude/controller-only-plan`（f570776）から分岐した `claude/controller-settings-folder`。
パスの接頭辞は `crates/bmz-player/src/`。

## 方針

- BMZ メニュー（egui）にはパッドの操作を足さない。パッドで動く選曲画面の「設定」フォルダに、足りない設定を足す。
- 分類
  - (a) 文字入力なし：今回追加する
  - (b) 文字入力が必要：段階 2（画面キーボード）
  - (c) OS ダイアログ・ドラッグ＆ドロップが必要：対象外。並べ替えは簡単なら上下移動にできるが、今回は見送り（下記）
  - 対象外（フォーク）：このフォークでは無効化済みの機能
- 変更は BMZ メニューと同じ経路で反映する。
  - プロファイルの切替：`request_profile_change(ProfileManagerAction::Switch)`（BMZ メニューの切替ボタンと同じ）
  - スキン：`Lr2SkinTarget::set_skin` / `lr2_set_skin_item`（LR2 選曲スキン内のスキン設定と同じ処理。スキンごとのオプション履歴も同じ）→ プロファイル保存 → `reload_skins`
  - キーコンフィグの既定に戻す：`apply_egui_key_config_action(RestoreDefaults)`
  - 曲フォルダ・難易度表：`config.toml` 保存 → `publish_song_scope`。再スキャンは `load_songs_and_reload`、取得は `spawn_table_fetches`
  - 入力デバイス：`config.toml` 保存 → `apply_egui_input_config`
  - 詳細オプション（実験的）：BMZ メニューの変更時と同じく、オプションの操作を閉じて選曲スキンを読み直す

## 実装

- `screens/settings_model.rs`
  - 新しいフォルダ：プロファイル、スキン（種類ごと）、ライブラリ（曲フォルダ・難易度表・未所持譜面の取得）、IR、システム
  - 新しい行：`SettingsChoice`（作成時に候補を並べ、選んだ値を確定時に反映）、`SettingsAction`（決定で実行）
  - 候補のうちプロファイル・コントローラー・スキン・難易度表の名前は、ウィンドウ側で `SettingsFolderExtras` に集めて一覧の読み込みスレッドへ渡す
- `screens/settings_edit.rs`：`ChoiceEditSession` を追加。編集中は下書きだけを動かし、確定まで設定を書き換えない。本体設定の編集の取消は、編集した節だけを戻す
- `config/settings_registry*`：プロファイルの項目（キー音の自動再生 3 種、UI 倍率、IR 3 種）
- `config/app_settings_registry.rs`：本体設定の項目（入力・選曲・スキャン・難易度表・譜面取得・スクリーンショット・ログ）
- `app/select_flow/settings_folder.rs`：確定時の反映。設定への書き込みは `apply_settings_choice_to_config`（テスト可能な関数）、保存と後処理は BMZ メニューと同じ関数
- `app/select_flow/controls.rs` は、設定フォルダの決定・確定・取消・増減の分岐に新しい行を足しただけ。`gamepad.rs` とキーコンフィグの待ち受けは触っていない
- `ui/skin_panel/lr2.rs`：LR2 選曲スキン内のスキン設定の処理を、全 14 種類と「値を直接選ぶ」形でも使えるようにした

## 検証

- `cargo fmt --check`、`cargo check -p bmz-player --locked`、`cargo clippy -p bmz-player --all-targets --locked -- -D warnings` は通過。
- `cargo test -p bmz-player --locked`：新しいテストを含めて通過。失敗は分岐元と同じ 5 件だけ（下記）。
  - `app::tests::select::cases_04::{select_snapshot_rows_append_values_only_to_config_bar_text, select_snapshot_rows_formats_app_config_values_and_audio_apply_action, select_snapshot_rows_preserves_settings_action_kinds}`、`screens::settings_edit::tests::edit_session_restore_reverts_new_dependent_settings`：OS の言語が英語の環境で、既定のプロファイルの言語が `en` になるため（日本語を前提にしたテスト）
  - `storage::scan::tests::scan_song_roots_skips_unreadable_subdirectory_and_keeps_accessible_files`：root で実行しているため、読み取り不可のフォルダが読めてしまう
  - スキンの submodule を取得した状態で実行した。分岐元で同じ条件で実行しても、この 5 件が失敗する。
- 実機では未確認（Linux のコンテナで、ウィンドウ・音声・コントローラーがない）。WinitApp を作るテストは Windows のイベントループが必要なため、反映処理は設定への書き込み部分を関数に分けてテストした。
